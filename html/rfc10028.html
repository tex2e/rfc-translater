Updates to Dynamic IPv6 Multicast Address Group IDs
動的 IPv6 マルチキャスト アドレス グループ ID の更新
Abstract
概要

This document describes limitations of the existing range of dynamic IPv6 multicast addresses specified in "Allocation Guidelines for IPv6 Multicast Addresses" (RFC 3307). It updates RFC 3307 by replacing these allocations with a new IANA registry in the "IPv6 Multicast Address Space" registry group. The document also defines initial contents of the new registry: a reduced allocation for the Multicast Address Dynamic Client Allocation Protocol (MADCAP) (RFC 2730), a range for Source-Specific Multicast (SSM), a Private Use range, a range for Experimental Use, and Solicited-Node multicast addresses (which were not previously noted in RFC 3307).

この文書では、「IPv6 マルチキャスト アドレスの割り当てガイドライン」(RFC 3307) で指定されている動的 IPv6 マルチキャスト アドレスの既存の範囲の制限について説明します。これらの割り当てを「IPv6 マルチキャスト アドレス スペース」レジストリ グループ内の新しい IANA レジストリに置き換えることにより、RFC 3307 を更新します。この文書では、新しいレジストリの初期内容も定義しています。つまり、マルチキャスト アドレス動的クライアント割り当てプロトコル (MADCAP) (RFC 2730) の割り当ての削減、ソース固有マルチキャスト (SSM) の範囲、プライベート使用範囲、実験使用範囲、および要請ノード マルチキャスト アドレス (これまで RFC 3307 には記載されていませんでした) です。

1. Introduction
1. はじめに

For IPv6 multicast addresses, [RFC3307], Section 2 defines the lower 32 bits of the IPv6 address, which are mapped directly to the link-layer, as the group ID, and then assigns ranges of group ID values based on how they are allocated. [RFC3307], Section 4.3 describes dynamic assignment of group ID values and lists two different approaches (server allocation and host allocation). However, both approaches are assigned the same range of group ID values, which means they cannot coexist without risking an address collision. Also concerning is that the group ID range for dynamic assignment overlaps with the range used for Solicited-Node multicast addresses (see [RFC4291], Section 2.7.1 for the definition of this range and [RFC10019] for the discussion of problems associated with duplicate group ID values on the network).

IPv6 マルチキャスト アドレスに関して、[RFC3307] のセクション 2 では、リンク層に直接マッピングされる IPv6 アドレスの下位 32 ビットをグループ ID として定義し、割り当て方法に基づいてグループ ID 値の範囲を割り当てます。[RFC3307] のセクション 4.3 では、グループ ID 値の動的割り当てについて説明し、2 つの異なるアプローチ (サーバー割り当てとホスト割り当て) をリストしています。ただし、どちらのアプローチにも同じ範囲のグループ ID 値が割り当てられるため、アドレス衝突の危険を冒さずに共存することはできません。また、動的割り当てのグループ ID 範囲が、Solicited-Node マルチキャスト アドレスに使用される範囲と重複していることも懸念されます (この範囲の定義については [RFC4291] のセクション 2.7.1 を、ネットワーク上の重複するグループ ID 値に関連する問題の議論については [RFC10019] を参照してください)。

Only one server allocation protocol has been defined at the time of writing (see [RFC2730]), but [RFC10019] advocates developing a decentralized, zero-configuration host allocation protocol. This document updates [RFC3307], Section 4.3 to allow multiple dynamic allocation protocols to coexist on the same network and so that dynamic IPv6 multicast group ID ranges use a registry to better align with current practices for protocol number assignment.

執筆時点では、サーバー割り当てプロトコルは 1 つだけ定義されていますが ([RFC2730] を参照)、[RFC10019] では、分散型のゼロ構成ホスト割り当てプロトコルの開発を提唱しています。この文書は [RFC3307] のセクション 4.3 を更新し、複数の動的割り当てプロトコルが同じネットワーク上で共存できるようにし、動的 IPv6 マルチキャスト グループ ID 範囲がレジストリを使用して、プロトコル番号割り当ての現在の慣行とより適切に連携できるようにします。

This document adheres to the IPv6 multicast address architecture outlined in [RFC4291], [RFC3307], [RFC7371], et al.

この文書は、[RFC4291]、[RFC3307]、[RFC7371] などで概説されている IPv6 マルチキャスト アドレス アーキテクチャに準拠しています。

2. Considerations for Source-Specific Multicast
2. ソース固有のマルチキャストに関する考慮事項

One of the benefits of Source-Specific Multicast (SSM) listed in [RFC4607], Section 1 is "[avoiding] the need for inter-host coordination when choosing source-specific addresses". SSM allows a host to subscribe to channel (S,G) and only receive packets for destination address G that are from source address S. This reduces the need for coordinated dynamic assignment of G because multiple distinct hosts could use the same value for G and traffic would still be directed to the node that requested the stream (see [RFC8815], Section 3.2.2).

[RFC4607] のセクション 1 にリストされている Source-Specific Multicast (SSM) の利点の 1 つは、「ソース固有のアドレスを選択する際のホスト間の調整の必要性を回避できる」ことです。SSM を使用すると、ホストはチャネル (S,G) にサブスクライブし、送信元アドレス S からの宛先アドレス G のパケットのみを受信できます。これにより、複数の個別のホストが G に同じ値を使用でき、トラフィックは引き続きストリームを要求したノードに送信されるため、G の調整された動的割り当ての必要性が軽減されます ([RFC8815]、セクション 3.2.2 を参照)。

However, SSM is not universally supported (see [RFC4607], Section 6 and [RFC8815], Section 3.1). This document defines a range of dynamic IPv6 multicast group IDs for use in environments that do support SSM.

ただし、SSM は広くサポートされているわけではありません ([RFC4607] のセクション 6 および [RFC8815] のセクション 3.1 を参照)。このドキュメントでは、SSM をサポートする環境で使用する動的 IPv6 マルチキャスト グループ ID の範囲を定義します。

Table 2: Updated Allocations

表 2: 更新された割り当て

This reduces the range previously available for the Multicast Address Dynamic Client Allocation Protocol (MADCAP) while still providing a sizable allocation. It also allocates ranges for SSM, Private Use, and Experimental Use. The Private Use range can be used in isolated deployments for purposes such as manual address allocation (see [RFC8126], Section 4.1). The Experimental Use range may be used for experimentation with new dynamic allocation protocols (see [RFC8126], Section 4.2). There are no restrictions on experimental scope; these IDs may be used to run experiments over the open Internet. Finally, this documents the range used for Solicited-Node multicast addresses. All remaining entries are reserved for future assignment as new protocols are developed.

これにより、マルチキャスト アドレス動的クライアント割り当てプロトコル (MADCAP) で以前に利用できた範囲が縮小されますが、依然としてかなりの割り当てが提供されます。また、SSM、私的使用、および実験的使用の範囲も割り当てられます。プライベート使用範囲は、手動アドレス割り当てなどの目的で分離された展開で使用できます ([RFC8126]、セクション 4.1 を参照)。実験的使用範囲は、新しい動的割り当てプロトコルの実験に使用できます ([RFC8126]、セクション 4.2 を参照)。実験範囲に制限はありません。これらの ID は、オープン インターネット上で実験を実行するために使用される場合があります。最後に、これは、Solicited-Node マルチキャスト アドレスに使用される範囲を文書化します。残りのエントリはすべて、新しいプロトコルが開発されたときの将来の割り当てのために予約されています。

4. Operational Considerations
4. 運用上の考慮事項

This document reduces the range of group ID values available for MADCAP [RFC2730]. At the time of writing, there is only one known implementation of MADCAP, and there are no known large-scale deployments. Any implementations of MADCAP (known or otherwise) should be updated to reflect the new group ID range set forth in Table 2. Any existing deployments of MADCAP should either use an updated implementation or operate in an environment without other IPv6 multicast address allocation protocols.

この文書では、MADCAP [RFC2730] で使用できるグループ ID 値の範囲を減らします。この記事の執筆時点では、MADCAP の既知の実装は 1 つだけであり、大規模な展開は知られていません。MADCAP の実装 (既知かどうかに関係なく) は、表 2 に示されている新しいグループ ID 範囲を反映するように更新する必要があります。MADCAP の既存の展開は、更新された実装を使用するか、他の IPv6 マルチキャスト アドレス割り当てプロトコルのない環境で動作する必要があります。

6. IANA Considerations
6. IANAの考慮事項

IANA has created a new registry named "Dynamic Multicast Group IDs" in the "IPv6 Multicast Address Space" registry group. The "Standards Action" registration policy is required to update the registry. Each entry in the registry contains the following fields:

IANA は、「IPv6 マルチキャスト アドレス スペース」レジストリ グループに「Dynamic Multicast Group IDs」という名前の新しいレジストリを作成しました。レジストリを更新するには、「Standards Action」登録ポリシーが必要です。レジストリの各エントリには次のフィールドが含まれます。

1. Range

1. 範囲

A range of 32-bit values rendered in hexadecimal. Values must be within the range 0x80000000 to 0xFFFFFFFF.

16 進数でレンダリングされた 32 ビット値の範囲。値は 0x80000000 ～ 0xFFFFFFFF の範囲内である必要があります。

2. Description

2. 説明

A description or protocol name assigned to the range.

範囲に割り当てられた説明またはプロトコル名。

3. Reference

3. 参照

A document describing the assignment.

課題を説明する文書。

The registry initially contains the entries listed in Table 2 and lists both [RFC3307] and this document as references.

レジストリには、表 2 にリストされているエントリが最初に含まれており、[RFC3307] とこのドキュメントの両方が参考資料としてリストされています。

IANA has also updated the references to "FF3X:0:0:0:0:0:8000:0-FF3X:0:0:0:0:0:FFFF:FFFF" in the "Unicast-based (Including SSM) Multicast Group IDs" registry in the "IPv6 Multicast Address Space" registry group. The registration procedure indicates that this range uses dynamic assignment according to the protocols listed in the new "Dynamic Multicast Group IDs" registry and includes a reference to this document. The description in the registry entry indicates that this range uses dynamic assignment according to the protocols listed in the new "Dynamic Multicast Group IDs" registry and the reference has been changed to this document.

IANA はまた、「IPv6 マルチキャスト アドレス スペース」レジストリ グループ内の「ユニキャストベース (SSM を含む) マルチキャスト グループ ID」レジストリ内の「FF3X:0:0:0:0:0:8000:0-FF3X:0:0:0:0:0:FFFF:FFFF」への参照を更新しました。登録手順には、この範囲が新しい「動的マルチキャスト グループ ID」レジストリにリストされているプロトコルに従って動的割り当てを使用することが示されており、このドキュメントへの参照が含まれています。レジストリ エントリの説明は、この範囲が新しい「動的マルチキャスト グループ ID」レジストリにリストされているプロトコルに従って動的割り当てを使用することを示しており、参照がこのドキュメントに変更されました。
