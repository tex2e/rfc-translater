This document describes the AEGIS-128L, AEGIS-256, AEGIS-128X, and AEGIS-256X AES-based authenticated encryption with associated data (AEAD) algorithms designed for high-performance applications. It also specifies their use as stream ciphers and message authentication codes (MACs).

1. Introduction
1. はじめに

This document describes the AEGIS family of authenticated encryption with associated data (AEAD) algorithms [AEGIS], which were chosen for high-performance applications in the CAESAR (Competition for Authenticated Encryption: Security, Applicability, and Robustness) competition.

このドキュメントでは、CAESAR (Competition for Authenticated Encryption: Security、Applicability、および Robustness) コンペティションで高性能アプリケーション向けに選ばれた、AEAD (Authenticated Encryption with Associated Data) アルゴリズムの AEGIS ファミリについて説明します。

Among the finalists, AEGIS-128 was chosen as the winner for this category. However, AEGIS-128L, another finalist, offers enhanced performance and a stronger security margin [ENP20] [JLD22] [LIMS21] [STSI23]. Additionally, AEGIS-256, which also reached the final round, provides 256-bit security and supports higher usage limits.

ファイナリストの中から、AEGIS-128 がこの部門の優勝者に選ばれました。ただし、もう 1 つの最終候補である AEGIS-128L は、強化されたパフォーマンスとより強力なセキュリティ マージンを提供します [ENP20] [JLD22] [LIMS21] [STSI23]。さらに、同じく最終ラウンドに進出した AEGIS-256 は、256 ビットのセキュリティを提供し、より高い使用制限をサポートします。

Therefore, this document specifies the following variants:

したがって、この文書では次のバリアントを指定します。

* AEGIS-128L, which has a 128-bit key, a 128-bit nonce, a 1024-bit state, a 128- or 256-bit authentication tag, and processes 256-bit input blocks.

* AEGIS-128L。128 ビットのキー、128 ビットのノンス、1024 ビットの状態、128 ビットまたは 256 ビットの認証タグを持ち、256 ビットの入力ブロックを処理します。

* AEGIS-256, which has a 256-bit key, a 256-bit nonce, a 768-bit state, a 128- or 256-bit authentication tag, and processes 128-bit input blocks.

* AEGIS-256。256 ビットのキー、256 ビットのノンス、768 ビットの状態、128 ビットまたは 256 ビットの認証タグを持ち、128 ビットの入力ブロックを処理します。

* AEGIS-128X, which is a mode based on AEGIS-128L, specialized for CPUs with large vector registers and vector AES instructions.

* AEGIS-128X は、AEGIS-128L をベースにしたモードで、大きなベクトル レジスタとベクトル AES 命令を備えた CPU に特化しています。

* AEGIS-256X, which is a mode based on AEGIS-256, specialized for CPUs with large vector registers and vector AES instructions.

* AEGIS-256X は、AEGIS-256 をベースにしたモードで、大きなベクトル レジスタとベクトル AES 命令を備えた CPU に特化しています。

All variants are inverse-free and constructed from the AES encryption round function [FIPS-AES].

すべてのバリアントは逆変換がなく、AES 暗号化ラウンド関数 [FIPS-AES] から構築されています。

The AEGIS cipher family offers performance that significantly exceeds AES-GCM on CPUs with AES instructions. Similarly, software implementations not using AES instructions can also be faster, although to a lesser extent.

AEGIS 暗号ファミリーは、AES 命令を備えた CPU 上で AES-GCM を大幅に超えるパフォーマンスを提供します。同様に、AES 命令を使用しないソフトウェア実装も、程度は低いものの高速化する可能性があります。

Unlike with AES-GCM, nonces can be safely chosen at random with no practical limit when using AEGIS-256 and AEGIS-256X. AEGIS-128L and AEGIS-128X also allow for more messages to be safely encrypted when using random nonces.

AES-GCM とは異なり、AEGIS-256 および AEGIS-256X を使用する場合は、実質的な制限なしでナンスをランダムに安全に選択できます。AEGIS-128L および AEGIS-128X では、ランダムな nonce を使用する場合に、より多くのメッセージを安全に暗号化することもできます。

With some existing AEAD schemes, such as AES-GCM, an attacker can generate a ciphertext that successfully decrypts under multiple different keys (a partitioning oracle attack) [LGR21]. This ability to craft a (ciphertext, authentication tag) pair that verifies under multiple keys significantly reduces the number of required interactions with the oracle to perform an exhaustive search, making it practical if the key space is small. For example, with password-based encryption, an attacker can guess a large number of passwords at a time by recursively submitting such a ciphertext to an oracle, which speeds up a password search by reducing it to a binary search.

AES-GCM などの一部の既存の AEAD スキームを使用すると、攻撃者は複数の異なるキーで復号化に成功する暗号文を生成できます (分割オラクル攻撃) [LGR21]。複数のキーの下で検証する (暗号文、認証タグ) ペアを作成できるこの機能により、徹底的な検索を実行するために必要なオラクルとの対話の数が大幅に削減され、キー空間が小さい場合に実用的になります。たとえば、パスワード ベースの暗号化では、攻撃者はそのような暗号文をオラクルに再帰的に送信することで、一度に大量のパスワードを推測できます。これにより、パスワード検索が二分探索に短縮され、高速化されます。

With AEGIS, finding distinct (key, nonce) pairs that successfully decrypt a given (associated data, ciphertext, authentication tag) tuple is believed to have a complexity that depends on the tag size. A 128-bit tag provides 64-bit committing security, which is generally acceptable for interactive protocols. With a 256-bit tag, finding a collision becomes impractical.

AEGIS では、特定の (関連データ、暗号文、認証タグ) タプルを正常に復号化する個別の (キー、ノンス) ペアを見つけることは、タグのサイズに依存する複雑さがあると考えられています。128 ビットのタグは、対話型プロトコルで一般に許容される 64 ビットのコミット セキュリティを提供します。256 ビットのタグでは、衝突を見つけるのが現実的ではなくなります。

Unlike most other AES-based AEAD constructions, leaking a state does not leak the key or previous states.

他のほとんどの AES ベースの AEAD 構造とは異なり、状態をリークしてもキーや以前の状態はリークされません。

Finally, an AEGIS key is not required after the initialization function, and there is no key schedule. Thus, ephemeral keys can be erased from memory before any data has been encrypted or decrypted, mitigating cold boot attacks.

最後に、初期化機能の後に AEGIS キーは必要なく、キーのスケジュールもありません。したがって、データが暗号化または復号化される前に一時キーをメモリから消去でき、コールド ブート攻撃を軽減できます。

Note that an earlier version of Hongjun Wu and Bart Preneel's paper introducing AEGIS specified AEGIS-128L and AEGIS-256 with a different Finalize function. We follow AEGIS v1.1 [AEGIS].

AEGIS を紹介する Honjun Wu と Bart Preneel の論文の以前のバージョンでは、異なるファイナライズ機能を備えた AEGIS-128L と AEGIS-256 が指定されていたことに注意してください。AEGIS v1.1 [AEGIS] に従います。

この文書は、Crypto Forum Research Group (CFRG) の総意を表しています。これは IETF 製品ではなく、標準でもありません。

3. The AEGIS-128L Algorithm
3. AEGIS-128L アルゴリズム

AEGIS-128L has a 1024-bit state, made of eight 128-bit blocks {S0, ...S7}.

AEGIS-128L には 8 つの 128 ビット ブロック {S0, ...S7} で構成される 1024 ビットの状態があります。

The parameters for this algorithm, as defined in Section 4 of [RFC5116], are:

[RFC5116] のセクション 4 で定義されているこのアルゴリズムのパラメータは次のとおりです。

* K_LEN (key length) is 16 bytes (128 bits).

* K_LEN (鍵の長さ) は 16 バイト (128 ビット) です。

* P_MAX (maximum length of the plaintext) is 2^61 - 1 bytes (2^64 - 8 bits).

* P_MAX (平文の最大長) は 2^61 - 1 バイト (2^64 - 8 ビット) です。

* A_MAX (maximum length of the associated data) is 2^61 - 1 bytes (2^64 - 8 bits).

* A_MAX (関連データの最大長) は 2^61 - 1 バイト (2^64 - 8 ビット) です。

* N_MIN (minimum nonce length) = N_MAX (maximum nonce length) and is 16 bytes (128 bits).

3.1. 認証された暗号化

   Finalize(ad_len_bits, msg_len_bits)

The Finalize function computes a 128- or 256-bit tag that authenticates the message and associated data.

Finalize 関数は、メッセージと関連データを認証する 128 ビットまたは 256 ビットのタグを計算します。

Inputs:

入力:

* ad_len_bits: the length of the associated data in bits.

* ad_len_bits: 関連するデータの長さ (ビット単位)。

* msg_len_bits: the length of the message in bits.

* msg_len_bits: メッセージの長さ (ビット単位)。

Outputs:

出力:

* タグ: 認証タグ。

Steps:

手順: 

   t = S3 ^ (LE64(ad_len_bits) || LE64(msg_len_bits))

   Repeat(7, Update(t))

   if tag_len_bits == 128:

5. Parallel Modes
5. パラレルモード

Some CPUs, such as Intel and Intel-compatible CPUs with the Vectorized AES (VAES) extensions, include instructions to efficiently apply the AES round function to a vector of AES blocks.

Intel および Vectorized AES (VAES) 拡張機能を備えた Intel 互換 CPU などの一部の CPU には、AES ブロックのベクトルに AES ラウンド関数を効率的に適用する命令が含まれています。

AEGIS-128X and AEGIS-256X are optional, specialized modes designed to take advantage of these instructions. They share the same properties as the ciphers they are based on but can be significantly faster on these platforms, even for short messages.

AEGIS-128X および AEGIS-256X は、これらの命令を活用するように設計されたオプションの特殊モードです。これらは、ベースとなる暗号と同じプロパティを共有しますが、これらのプラットフォームでは、短いメッセージであっても大幅に高速化されます。

AEGIS-128X and AEGIS-256X are parallel evaluations of multiple AEGIS-128L and AEGIS-256 instances, respectively, with distinct initial states. On CPUs with wide vector registers, different states can be stored in different 128-bit lanes of the same vector register, allowing parallel updates using vector instructions.

AEGIS-128X および AEGIS-256X は、それぞれ、異なる初期状態を持つ複数の AEGIS-128L および AEGIS-256 インスタンスの並列評価です。幅の広いベクトル レジスタを備えた CPU では、異なる状態を同じベクトル レジスタの異なる 128 ビット レーンに保存できるため、ベクトル命令を使用した並列更新が可能になります。

The modes are parameterized by the parallelism degree. With 256-bit registers, two parallel operations can be applied to 128-bit AES blocks. With 512-bit registers, the number of instances can be raised to four.

モードは並列度によってパラメータ化されます。256 ビット レジスタを使用すると、2 つの並列操作を 128 ビット AES ブロックに適用できます。512 ビット レジスタを使用すると、インスタンスの数は 4 つまで増やすことができます。

The state of a parallel mode is represented as a vector of AEGIS-128L or AEGIS-256 states.

パラレル モードの状態は、AEGIS-128L または AEGIS-256 状態のベクトルとして表されます。

5.1. Additional Conventions and Definitions
5.1. 追加の規則と定義

* D: the degree of parallelism.

* D: 並列度。

* R: the absorption and output rate of the mode. With AEGIS-128X, the rate is 256 * D bits. With AEGIS-256X, the rate is 128 * D bits.

* R: モードの吸収率と出力率。AEGIS-128X の場合、レートは 256 * D ビットです。AEGIS-256X の場合、レートは 128 * D ビットです。

* V[j,i]: the j-th AES block of the i-th state. i is in the [0..D) range. For AEGIS-128X, j is in the [0..8) range, while for AEGIS-256X, j is in the [0..6) range.

* V[j,i]: i 番目の状態の j 番目の AES ブロック。i は [0..D) の範囲にあります。AEGIS-128X の場合、j は [0..8) の範囲にありますが、AEGIS-256X の場合、j は [0..6) の範囲にあります。

* V'[j,i]: the j-th AES block of the next i-th state.

* V'[j,i]: 次の i 番目の状態の j 番目の AES ブロック。

* ctx[i]: the i-th context separator. This is a 128-bit mask made of a byte representing the state index, followed by a byte representing the highest index and 112 all-zero bits.

* ctx[i]: i 番目のコンテキスト区切り文字。これは、状態インデックスを表すバイト、その後に最高のインデックスを表すバイト、および 112 個のオール ゼロ ビットで構成される 128 ビット マスクです。

5.2. Authenticated Encryption
5.2. 認証された暗号化 
   Encrypt(msg, ad, key, nonce)

The Encrypt function of AEGIS-128X resembles that of AEGIS-128L. Similarly, the Encrypt function of AEGIS-256X mirrors that of AEGIS-256. However, both process R-bit input blocks per update.

AEGIS-128X の暗号化機能は AEGIS-128L の暗号化機能と似ています。同様に、AEGIS-256X の暗号化機能は AEGIS-256 の暗号化機能を反映しています。ただし、どちらも更新ごとに R ビットの入力ブロックを処理します。

Steps:

手順: 

   Init(key, nonce)

   ct = {}

   ad_blocks = Split(ZeroPad(ad, R), R)
   for ai in ad_blocks:
       Absorb(ai)

   msg_blocks = Split(ZeroPad(msg, R), R)
   for xi in msg_blocks:
       ct = ct || Enc(xi)

   tag = Finalize(|ad|, |msg|)
   ct = Truncate(ct, |msg|)

   return ct and tag
5.3. Authenticated Decryption
5.3. 認証された復号化 
   Decrypt(ct, tag, ad, key, nonce)

The Decrypt function of AEGIS-128X resembles that of AEGIS-128L. Similarly, the Decrypt function of AEGIS-256X mirrors that of AEGIS-256. However, both process R-bit input blocks per update.

AEGIS-128X の復号化機能は AEGIS-128L の復号化機能と似ています。同様に、AEGIS-256X の復号化機能は AEGIS-256 の復号化機能を反映しています。ただし、どちらも更新ごとに R ビットの入力ブロックを処理します。

Steps:

手順: 

   Init(key, nonce)

   msg = {}

   ad_blocks = Split(ZeroPad(ad, R), R)
   for ai in ad_blocks:
       Absorb(ai)

   ct_blocks = Split(ct, R)
   cn = Tail(ct, |ct| mod R)

   for ci in ct_blocks:
       msg = msg || Dec(ci)

   if cn is not empty:
       msg = msg || DecPartial(cn)

   expected_tag = Finalize(|ad|, |msg|)

       erase msg
       erase expected_tag

   else:
       return msg

5.4.1. アップデート機能 
   Update(M0, M1)

The AEGIS-128X Update function is similar to the AEGIS-128L Update function but absorbs R (= 256 * D) bits at once. M0 and M1 are 128 * D bits instead of 128 bits, but they are split into 128-bit blocks, each of which updates a different AEGIS-128L state.

       V[1,i]  = V'[1,i]
       V[2,i]  = V'[2,i]
       V[3,i]  = V'[3,i]

Init 関数は、同じキーとノンスで、異なるコンテキスト ctx[i] を使用して D AEGIS-128L 状態のベクトルを初期化します。すべての初期化更新の前に、ctx[i] は V[3,i] と V[7,i] に XOR 演算されます。

手順:

       V[1,i] = C1
       V[2,i] = C0
       V[3,i] = C1

   )

5.6. Implementation Considerations
5.6. 実装に関する考慮事項

AEGIS-128X and AEGIS-256X with a degree of 1 are identical to AEGIS-128L and AEGIS-256, respectively. This property can be used to reduce the size of a generic implementation.

次数 1 の AEGIS-128X および AEGIS-256X は、それぞれ AEGIS-128L および AEGIS-256 と同一です。このプロパティを使用すると、汎用実装のサイズを削減できます。

In AEGIS-128X, V can be represented as eight 256-bit registers (when D = 2) or eight 512-bit registers (when D = 4). In AEGIS-256X, V can be represented as six 256-bit registers (when D = 2) or six 512-bit registers (when D = 4). With this representation, loops over 0..D in the above pseudocode can be replaced by vector instructions.

AEGIS-128X では、V は 8 つの 256 ビット レジスタ (D = 2 の場合) または 8 つの 512 ビット レジスタ (D = 4 の場合) として表すことができます。AEGIS-256X では、V は 6 つの 256 ビット レジスタ (D = 2 の場合) または 6 つの 512 ビット レジスタ (D = 4 の場合) として表すことができます。この表現を使用すると、上記の疑似コード内の 0..D にわたるループをベクトル命令に置き換えることができます。

5.7. Operational Considerations
5.7. 運用上の考慮事項

The AEGIS parallel modes are specialized and can only improve performance on specific CPUs.

AEGIS 並列モードは特殊化されており、特定の CPU でのみパフォーマンスを向上させることができます。

The degrees of parallelism that implementations are encouraged to support are 2 (for CPUs with 256-bit registers) and 4 (for CPUs with 512-bit registers). The resulting algorithms are called AEGIS-128X2, AEGIS-128X4, AEGIS-256X2, and AEGIS-256X4.

8.3.2. The FinalizeMac Function
8.3.2. FinalizeMac 関数 
   FinalizeMac(data_len_bits)

The FinalizeMac function computes a 128- or 256-bit tag that authenticates the input data.

FinalizeMac 関数は、入力データを認証する 128 ビットまたは 256 ビットのタグを計算します。

It finalizes all the instances, absorbs the resulting tags into the first state, and computes the final tag using that single state, as done in AEGIS-128L.

AEGIS-128L で行われているように、すべてのインスタンスを終了し、結果のタグを最初の状態に吸収し、その単一の状態を使用して最終的なタグを計算します。

Steps:

手順: 

   t = {}
   u = LE64(data_len_bits) || LE64(tag_len_bits)
   for i in 0..D:
       t = t || (V[2,i] ^ u)

   Repeat(7, Update(t, t))

   tags = {}
   if tag_len_bits == 128:
       for i in 0..D: # tag from state 0 is included
           ti = V[0,i] ^ V[1,i] ^ V[2,i] ^ V[3,i] ^
                V[4,i] ^ V[5,i] ^ V[6,i]
           tags = tags || ti

   else:              # 256 bits
       for i in 1..D: # tag from state 0 is skipped
           ti0 = V[0,i] ^ V[1,i] ^ V[2,i] ^ V[3,i]
           ti1 = V[4,i] ^ V[5,i] ^ V[6,i] ^ V[7,i]
           tags = tags || (ti0 || ti1)

   if D > 1:
       # Absorb tags into state 0; other states are not used anymore
       for v in Split(tags, 256):
           x0, x1 = Split(v, 128)
           Absorb(ZeroPad(x0, R / 2) || ZeroPad(x1, R / 2))

       u = LE64(D) || LE64(tag_len_bits)
       t = ZeroPad(V[2,0] ^ u, R)
       Repeat(7, Update(t, t))

   if tag_len_bits == 128:
       tag = V[0,0] ^ V[1,0] ^ V[2,0] ^ V[3,0] ^
             V[4,0] ^ V[5,0] ^ V[6,0]
   else:            # 256 bits
       t0 = V[0,0] ^ V[1,0] ^ V[2,0] ^ V[3,0]
       t1 = V[4,0] ^ V[5,0] ^ V[6,0] ^ V[7,0]
       tag = t0 || t1

   return tag

8.4.2. The FinalizeMac Function
8.4.2. FinalizeMac 関数 
   FinalizeMac(data_len_bits)

The FinalizeMac function computes a 128- or 256-bit tag that authenticates the input data.

FinalizeMac 関数は、入力データを認証する 128 ビットまたは 256 ビットのタグを計算します。

It finalizes all the instances, absorbs the resulting tags into the first state, and computes the final tag using that single state, as done in AEGIS-256.

AEGIS-256 で行われているように、すべてのインスタンスを終了し、結果のタグを最初の状態に吸収し、その単一の状態を使用して最終的なタグを計算します。 

   t = {}
   u = LE64(data_len_bits) || LE64(tag_len_bits)
   for i in 0..D:
       t = t || (V[3,i] ^ u)

   Repeat(7, Update(t))

   tags = {}
   if tag_len_bits == 128:
       for i in 1..D: # tag from state 0 is skipped
           ti = V[0,i] ^ V[1,i] ^ V[2,i] ^ V[3,i] ^ V[4,i] ^ V[5,i]
           tags = tags || ti

   else:              # 256 bits
       for i in 1..D: # tag from state 0 is skipped
           ti0 = V[0,i] ^ V[1,i] ^ V[2,i]
           ti1 = V[3,i] ^ V[4,i] ^ V[5,i]
           tags = tags || (ti0 || ti1)

   if D > 1:
       # Absorb tags into state 0; other states are not used anymore
       for v in Split(tags, 128):
           Absorb(ZeroPad(v, R))

       u = LE64(D) || LE64(tag_len_bits)
       t = ZeroPad(V[3,0] ^ u, R)
       Repeat(7, Update(t))

   if tag_len_bits == 128:
       tag = V[0,0] ^ V[1,0] ^ V[2,0] ^ V[3,0] ^ V[4,0] ^ V[5,0]
   else:            # 256 bits
       t0 = V[0,0] ^ V[1,0] ^ V[2,0]
       t1 = V[3,0] ^ V[4,0] ^ V[5,0]
       tag = t0 || t1

   return tag
9. Security Considerations
9. セキュリティに関する考慮事項
9.1. Usage Guidelines
9.1. 使用ガイドライン
9.1.1. Key and Nonce Selection
9.1.1. キーとナンスの選択

When AEGIS is used for encryption, a nonce MUST only be used once for a given key, even with different tag lengths. Failure to do so would immediately reveal the bitwise difference between two messages.

AEGIS を暗号化に使用する場合、タグ長が異なっていても、ノンスは特定のキーに対して 1 回だけ使用しなければなりません (MUST)。そうしないと、2 つのメッセージ間のビット単位の違いがすぐに明らかになります。

Every key MUST be randomly chosen from a uniform distribution.

すべてのキーは一様な分布からランダムに選択されなければなりません。

The nonce MAY be public or predictable. It can be a counter, the output of a permutation, or a generator with a long period.

nonce は public または予測可能なものであってもよい (MAY)。これは、カウンター、順列の出力、または長周期のジェネレーターである可能性があります。

With AEGIS-128L and AEGIS-128X, random nonces can safely encrypt up to 2^48 messages using the same key with negligible (~2^-33) collision probability. This is consistent with Section 8 of [SP800-38D].

AEGIS-128L および AEGIS-128X では、ランダムなナンスにより、衝突確率が無視できる (~2^-33) の同じキーを使用して最大 2^48 メッセージを安全に暗号化できます。これは、[SP800-38D] のセクション 8 と一致しています。

With AEGIS-256 and AEGIS-256X, random nonces can be used with no practical limits.

AEGIS-256 および AEGIS-256X では、ランダムなノンスを実質的な制限なく使用できます。

9.1.2. Committing Security
9.1.2. セキュリティのコミット

An authentication tag may verify under multiple keys, nonces, or associated data, but AEGIS is assumed to be key committing in the receiver-binding game. This mitigates common attacks when used with low-entropy keys such as passwords. Finding distinct keys and/or nonces that successfully verify the same (ad, ct, tag) tuple is expected to require ~2^64 attempts with a 128-bit authentication tag and ~2^128 attempts with a 256-bit tag.

認証タグは複数のキー、ノンス、または関連データに基づいて検証できますが、AEGIS は受信機バインディング ゲームでのキーコミットであると想定されます。これにより、パスワードなどの低エントロピーのキーを使用した場合の一般的な攻撃が軽減されます。同じ (ad、ct、tag) タプルを正常に検証する個別のキーやノンスを見つけるには、128 ビットの認証タグでは ~2^64 回の試行、256 ビットのタグでは ~2^128 回の試行が必要になることが予想されます。

AEGIS is fully committing in the restricted setting where an adversary cannot control the associated data. As shown in [IR23], with the ability to alter the associated data, it is possible to efficiently find multiple keys that will verify the same authenticated ciphertext.

AEGIS は、攻撃者が関連データを制御できない制限された設定で完全にコミットします。[IR23] に示されているように、関連データを変更する機能により、同じ認証された暗号文を検証する複数の鍵を効率的に見つけることが可能になります。

Protocols mandating a fully committing scheme without that restriction can provide the associated data as input to a cryptographic hash function and use the output as the ad parameter of the Encrypt and Decrypt functions. The selected hash function must ensure a minimum of 128-bit collision and preimage resistance. An instance of such a function is SHA-256 [RFC6234].

この制限のないフルコミットスキームを義務付けるプロトコルでは、関連データを暗号化ハッシュ関数への入力として提供し、その出力を暗号化関数と復号化関数の ad パラメーターとして使用できます。選択したハッシュ関数は、少なくとも 128 ビットの衝突とプリイメージ耐性を保証する必要があります。このような関数のインスタンスは SHA-256 [RFC6234] です。

Alternatively, the associated data can be fed into a collision-resistant key derivation function (KDF), such as the HMAC-based key derivation function (HKDF) [RFC5869], via the info input to derive the key parameter. The ad parameter can then be left empty. Note that the salt input MUST NOT be used since large salts get hashed, which affects commitment. Furthermore, this requires values concatenated to form the info input to be unambiguously encoded, like by appending their lengths.

あるいは、関連データを、情報入力を介して、HMAC ベースの鍵導出関数 (HKDF) [RFC5869] などの衝突耐性のある鍵導出関数 (KDF) に入力して、鍵パラメーターを導出することができます。広告パラメータは空のままにすることができます。大きなソルトはハッシュ化され、コミットメントに影響を与えるため、ソルト入力は使用してはいけないことに注意してください。さらに、これには、長さを追加するなどして、情報入力を形成するために連結された値が明確にエンコードされる必要があります。

9.1.3. Multi-User Security
9.1.3. マルチユーザーセキュリティ

AEGIS nonces match the size of the key. AEGIS-128L and AEGIS-128X feature 128-bit nonces, offering an extra 32 bits compared to the commonly used AEADs in IETF protocols at the time of writing. The AEGIS-256 and AEGIS-256X variants provide even larger nonces. With 192 random bits, 64 bits remain available to optionally encode additional information.

AEGIS ノンスはキーのサイズと一致します。AEGIS-128L および AEGIS-128X は 128 ビットのノンスを備えており、執筆時点で IETF プロトコルで一般的に使用されている AEAD と比較して、追加の 32 ビットを提供します。AEGIS-256 および AEGIS-256X のバリアントでは、さらに大きなノンスが提供されます。192 のランダム ビットがあるため、オプションで追加情報をエンコードするために 64 ビットが残ります。

In all these variants, unused nonce bits can encode a key identifier, enhancing multi-user security. If every key has a unique identifier, multi-target attacks do not provide any advantage over single-target attacks.

これらすべてのバリアントでは、未使用のノンス ビットでキー識別子をエンコードできるため、マルチユーザーのセキュリティが強化されます。すべてのキーに一意の識別子がある場合、マルチターゲット攻撃は単一ターゲット攻撃よりも利点がありません。

9.2. Implementation Security
9.2. 実装のセキュリティ

If tag verification fails, the unverified plaintext and computed authentication tag MUST NOT be released. As shown in [VV18], even a partial leak of the plaintext without verification facilitates chosen ciphertext attacks.

タグ検証が失敗した場合、未検証の平文および計算された認証タグを解放してはなりません (MUST NOT)。[VV18] に示されているように、検証なしで平文が部分的に漏洩した場合でも、選択された暗号文攻撃が容易になります。

The security of AEGIS against timing and physical attacks is limited by the implementation of the underlying AESRound function. Failure to implement AESRound in a fashion safe against timing and physical attacks, such as differential power analysis, timing analysis, or fault injection attacks, may lead to leakage of secret key material or state information. The exact mitigations required for timing and physical attacks depend on the threat model in question.

タイミング攻撃および物理的攻撃に対する AEGIS のセキュリティは、基礎となる AESRound 関数の実装によって制限されます。差動電力解析、タイミング解析、フォールトインジェクション攻撃などのタイミング攻撃や物理的攻撃に対して安全な方法で AESRound を実装しないと、秘密鍵マテリアルや状態情報の漏洩につながる可能性があります。タイミング攻撃と物理的攻撃に必要な正確な軽減策は、問題の脅威モデルによって異なります。

Regardless of the variant, the key and nonce are only required by the Init function; other functions only depend on the resulting state. Therefore, implementations can overwrite ephemeral keys with zeros right after the last Update call of the initialization function.

バリアントに関係なく、キーとナンスは Init 関数でのみ必要です。他の関数は結果の状態にのみ依存します。したがって、実装では、初期化関数の最後の Update 呼び出しの直後に一時キーをゼロで上書きできます。

9.3. Security Guarantees
9.3. 安全性の保証

AEGIS-256 offers 256-bit security against plaintext and state recovery, whereas AEGIS-128L offers 128-bit security.

AEGIS-256 は平文および状態回復に対して 256 ビットのセキュリティを提供しますが、AEGIS-128L は 128 ビットのセキュリティを提供します。

Under the assumption that the secret key is unknown to the attacker, all AEGIS variants offer at least 128-bit security against forgery attacks.

秘密鍵が攻撃者に知られていないという想定の下、すべての AEGIS 亜種は、偽造攻撃に対して少なくとも 128 ビットのセキュリティを提供します。

Encrypting the same message with the same key and nonce but different associated data generates distinct ciphertexts that do not reveal any additional information about the message. However, (key, nonce) pairs MUST NOT be reused, even if the associated data differs.

同じメッセージを同じキーとナンスで異なる関連データで暗号化すると、メッセージに関する追加情報を明らかにしない個別の暗号文が生成されます。ただし、たとえ関連するデータが異なっていても、(key, nonce) ペアを再利用してはなりません (MUST NOT)。

AEGIS has been shown to have reforgeability resilience in [FLLW17]. Without the ability to set the associated data, a successful forgery does not increase the probability of subsequent forgeries.

AEGIS は [FLLW17] で再鍛造可能性の回復力があることが示されています。関連データを設定する機能がなければ、偽造が成功しても、その後の偽造の可能性は高まりません。

AEGIS-128X and AEGIS-256X share the same security properties and requirements as AEGIS-128L and AEGIS-256, respectively. In particular, the security level and usage limits remain the same [D23].

AEGIS-128X および AEGIS-256X は、それぞれ AEGIS-128L および AEGIS-256 と同じセキュリティ プロパティおよび要件を共有します。特に、セキュリティ レベルと使用制限は変わりません [D23]。

AEGIS is considered secure against guess-and-determine attacks aimed at recovering the state from observed ciphertexts.

AEGIS は、観察された暗号文から状態を回復することを目的とした推測決定攻撃に対して安全であると考えられています。

This resilience extends to quantum adversaries operating within the Q1 model, where the attacker has access to a quantum computer but is restricted to classical (non-quantum) communications with the systems under attack. In this model, quantum attacks offer no practical advantage in decrypting previously recorded ciphertexts or in recovering the encryption key.

この回復力は、Q1 モデル内で動作する量子攻撃者にも拡張されます。攻撃者は量子コンピューターにアクセスできますが、攻撃対象のシステムとの古典的な (非量子) 通信に制限されます。このモデルでは、量子攻撃は、以前に記録された暗号文の解読や暗号化キーの回復において実質的な利点を提供しません。

This document extends the AEGIS specification [AEGIS] by introducing optional support for 256-bit authentication tags, which are constructed similarly to the 128-bit tags. As shown in [SSI24], with 256-bit tags, all AEGIS variants achieve more than 128-bit security against forgery by differential attacks.

この文書は、128 ビット タグと同様に構築される 256 ビット認証タグのオプション サポートを導入することにより、AEGIS 仕様 [AEGIS] を拡張します。[SSI24] に示されているように、256 ビットのタグを使用すると、すべての AEGIS 亜種は差分攻撃による偽造に対して 128 ビット以上のセキュリティを実現します。

Security analyses of AEGIS can be found in [AEGIS], [M14], [FLLW17], [ENP20], [LIMS21], [JLD22], [STSI23], [IR23], [BS23], [AIKRS24], and [SSI24].

AEGIS のセキュリティ分析は、[AEGIS]、[M14]、[FLLW17]、[ENP20]、[LIMS21]、[JLD22]、[STSI23]、[IR23]、[BS23]、[AIKRS24]、および [SSI24] にあります。
