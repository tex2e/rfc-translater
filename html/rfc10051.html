Task Extensions to iCalendar

Abstract
概要

The "VTODO" calendar component in the Internet Calendaring and Scheduling Core Object Specification (iCalendar; RFC 5545) has seen limited adoption and use, mainly for personal reminders and to-do lists.

Internet Calendaring and Scheduling Core Object Specification (iCalendar; RFC 5545) の "VTODO" カレンダーコンポーネントは、主に個人のリマインダーやToDoリストに用いられるにとどまり、採用や利用が限定的でした。

This document updates RFC 5545 and defines extensions to "VTODO" to provide improved status tracking, scheduling, and specification of tasks to allow its use in other contexts, such as process control and project management.

本文書は RFC 5545 を更新し、ステータス追跡、スケジューリング、タスクの仕様を改善して、プロセス制御やプロジェクト管理といった他の文脈でも "VTODO" を使えるようにするための拡張を定義します。

It also defines how Calendaring Extensions to WebDAV (CalDAV) (RFC 4791) servers can be extended to support certain automated task management behaviors.

また、Calendaring Extensions to WebDAV (CalDAV) (RFC 4791) サーバーを拡張して、特定の自動化されたタスク管理の動作をサポートする方法も定義します。

1. Introduction
1. はじめに

This document specifies extensions to the Internet Calendaring and Scheduling Core Object Specification (iCalendar) [RFC5545] and associated protocols in order to enhance the structured communication and execution of tasks. The enhancements allow for the communication, time planning, and scheduling of tasks by and between automated systems (e.g., taxi dispatch systems, smart power grids [WsCalendar], and business process management systems), as well as for human-centered tasks.

本文書は、タスクの構造化された通信と実行を強化するために、Internet Calendaring and Scheduling Core Object Specification (iCalendar) [RFC5545] および関連プロトコルの拡張を規定します。これらの拡張により、自動化システム間（例: タクシー配車システム、スマートグリッド [WsCalendar]、ビジネスプロセス管理システム）での、またそれらと人との間でのタスクの通信、時間計画、スケジューリングが可能になり、人間中心のタスクにも対応できます。

A "task" is a representation of an item of work assigned to an individual or organization. In the iCalendar Object Model [RFC5545] the representation of tasks is by "VTODO" calendar components. Tasks can be identified in a number of situations, either informally as ad hoc tasks in personal to-do lists or more formally in business processes (ranging from repetitive workflows to adaptive cases and trouble ticketing) and project management (whether for large-scale construction projects or collaborative software development).

"タスク" とは、個人または組織に割り当てられた作業項目を表現したものです。iCalendar オブジェクトモデル [RFC5545] では、タスクは "VTODO" カレンダーコンポーネントで表現されます。タスクは様々な場面で識別されます。個人のToDoリストにおける場当たり的なアドホックタスクのような非公式なものから、ビジネスプロセス（反復的なワークフローから適応型ケース、トラブルチケット管理まで）やプロジェクト管理（大規模な建設プロジェクトから共同でのソフトウェア開発まで）におけるより公式なものまであります。

The extensions specified in this document enhance and standardize the following:

本文書で規定する拡張は、次の事項を強化し標準化します。

* The specification of tasks: How a task type is defined and the relationships between tasks; see Section 4.

* タスクの仕様: タスク種別の定義方法とタスク間の関係。セクション4を参照してください。

* Task planning and scheduling: Improved specification of deadlines and estimated time for completion; see Section 5.

* タスクの計画とスケジューリング: 期限と完了までの見積時間の仕様の改善。セクション5を参照してください。

* Task assignment and status reporting: The addition of "VSTATUS" (Section 8) allows for more detailed reports; see Section 7.

* タスクの割り当てとステータス報告: "VSTATUS" (セクション8) の追加により、より詳細な報告が可能になります。セクション7を参照してください。

These extensions are defined within the context of an overall architecture for task calendaring and scheduling, which elaborates that supported by [RFC5545] and related standards.

これらの拡張は、[RFC5545] および関連標準がサポートするものを詳細化した、タスクのカレンダリングとスケジューリングの全体アーキテクチャの文脈の中で定義されます。

Terms defined and used in this specification include:

本仕様で定義され使用される用語には、次のものがあります。

Assignee:

担当者:

A calendar user assigned to perform a given task. An assignee is equivalent to an "Attendee" of a task.

特定のタスクを実行するよう割り当てられたカレンダーユーザー。担当者は、タスクの "Attendee" (出席者) と同等です。

BPMS:

BPMS:

Business Process Management Software

ビジネスプロセス管理ソフトウェア

CU:

CU:

Calendar User. A person or software system that accesses or modifies calendar information.

カレンダーユーザー。カレンダー情報にアクセスまたは変更する人またはソフトウェアシステム。

CUA:

CUA:

Calendar User Agent. This may be one of the following:

カレンダーユーザーエージェント。次のいずれかです。

1. Software with which the CU communicates with a calendar service or local calendar store to access calendar information.

1. CUがカレンダー情報にアクセスするために、カレンダーサービスまたはローカルのカレンダーストアと通信するソフトウェア。

2. Software that gathers calendar data on the CU's behalf.

2. CUに代わってカレンダーデータを収集するソフトウェア。

Candidate:

候補者:

A calendar user who might be able to perform a given task, prior to actually being assigned the task, e.g., a dispatcher has a list of taxi drivers (candidates) from which one will be selected to pick up a passenger.

実際にタスクが割り当てられる前の、特定のタスクを実行できる可能性のあるカレンダーユーザー。例えば、ディスパッチャーがタクシー運転手（候補者）の一覧を持ち、その中から乗客を迎えに行く1人が選ばれる場合です。

Organizer:

オーガナイザー:

A calendar user who creates a calendar item, requests free/busy information, or publishes free/busy information. It is an "Organizer" who invites "Attendees" [RFC5545].

カレンダー項目を作成する、free/busy情報を要求する、またはfree/busy情報を公開するカレンダーユーザー。"Organizer" は "Attendees" を招待する者です [RFC5545]。

Observer:

オブザーバー:

A calendar user interested in a calendar component, e.g., a manager may have interest in all tasks that have not been completed. Often represented as an "Attendee" with the "role" parameter set to NON-PARTICIPANT.

カレンダーコンポーネントに関心を持つカレンダーユーザー。例えば、マネージャーが完了していないすべてのタスクに関心を持つ場合があります。多くの場合、"role" パラメータを NON-PARTICIPANT に設定した "Attendee" として表現されます。

Resource:

リソース:

A resource in the scheduling context is any shared entity that can be scheduled by a calendar user but does not control its own attendance status. Examples of such resources are locations such as a bookable conference room or equipment such as projectors.

スケジューリングの文脈におけるリソースとは、カレンダーユーザーがスケジュールできるが、自身の出席ステータスを制御しない共有エンティティを指します。このようなリソースの例として、予約可能な会議室などの場所や、プロジェクターなどの機器があります。

Task:

タスク:

A representation of an item of work that can be assigned to one or more task actor assignees. In [RFC5545], these are "VTODO" calendar components, which are groupings of component properties and possibly "VALARM" calendar components that represent an action item or assignment.

1人以上のタスクアクターである担当者に割り当てることができる作業項目の表現。[RFC5545] では、これらは "VTODO" カレンダーコンポーネントであり、アクション項目または割り当てを表すコンポーネントプロパティ、および場合によっては "VALARM" カレンダーコンポーネントをまとめたものです。

2. Task Architecture
2. タスクアーキテクチャ

A reference architecture for task calendaring and scheduling is defined in order to identify the key logical elements involved in task management and the interfaces between them to enable interoperability. Central to this architecture is the Calendar and Scheduling System. The logical elements identified here establish an appropriate separation of concerns and clarify the responsibilities of different elements. However, the architecture does not prescribe the binding or packaging of elements, i.e., software systems may be developed where some elements are tightly bound and the interfaces between bound elements are not exposed. The task architecture is also described in [TARCH].

タスクのカレンダリングとスケジューリングのリファレンスアーキテクチャは、タスク管理に関わる主要な論理要素とそれらの間のインタフェースを特定し、相互運用性を実現するために定義されています。このアーキテクチャの中心となるのは、カレンダーおよびスケジューリングシステムです。ここで特定される論理要素は、適切な関心の分離を確立し、各要素の責務を明確にします。ただし、このアーキテクチャは要素の結合やパッケージ化の方法を規定するものではありません。すなわち、一部の要素が密に結合され、結合された要素間のインタフェースが公開されないソフトウェアシステムが開発されることもあります。タスクアーキテクチャは [TARCH] でも説明されています。

2.1. Task Architecture Elements
2.1. タスクアーキテクチャの要素

The following logical elements form the task architecture that this specification is based on:

以下の論理要素が、本仕様の基礎となるタスクアーキテクチャを構成します。

Task Actors:

タスクアクター:

Various calendar users that may be involved in the monitoring or performing of a task. The set of actors includes Organizers, Observers, Resources, Assignees, and Candidates.

タスクの監視または実行に関与しうる各種のカレンダーユーザー。アクターの集合には、オーガナイザー、オブザーバー、リソース、担当者、候補者が含まれます。

Task Organizer:

タスクオーガナイザー:

The creator of a task who also determines task assignment and scheduling and monitors task progress.

タスクの作成者であり、タスクの割り当てとスケジューリングを決定し、タスクの進捗を監視する者。

Task Domain Data:

タスクドメインデータ:

This is any domain-specific data that may be acted on or that provides context for performing a task.

タスクに対して操作される可能性のある、またはタスクを実行するための文脈を提供する、あらゆるドメイン固有のデータ。

Task-Specific Application:

タスク固有アプリケーション:

A task-specific application renders the data concerning the task (including task domain data) for presentation and manipulation by a task actor.

タスク固有アプリケーションは、タスクアクターによる提示と操作のために、タスクに関するデータ（タスクドメインデータを含む）を表示します。

Process Logic:

プロセスロジック:

Determines under what conditions one or more tasks are generated and the actions to take upon task completion or upon the occurrence (or non-occurrence) of some other status event.

どのような条件で1つ以上のタスクを生成するか、およびタスクの完了時、または他のステータスイベントの発生時（または不発生時）にどのようなアクションを取るかを決定するもの。

Task Trigger:

タスクトリガー:

An event that gives rise to the generation of a task according to Process Logic. Task triggers can come from many sources including, for example, a task being requested through the calendaring system or a status change in the progression of a business process being managed by a business process management or enterprise resource planning (ERP) system.

プロセスロジックに従ってタスクの生成を引き起こすイベント。タスクトリガーは多くの発生源から生じえます。例えば、カレンダリングシステムを通じて要求されたタスクや、ビジネスプロセス管理システムまたはエンタープライズリソースプランニング (ERP) システムによって管理されるビジネスプロセスの進行におけるステータス変化などです。

Task Assignment Rules:

タスク割り当てルール:

Govern how actors are assigned to a task. A range of different assignment patterns [WfRP] may be considered, including the two general cases:

アクターをタスクにどのように割り当てるかを定めるもの。次の2つの一般的なケースを含め、さまざまな割り当てパターン [WfRP] が考えられます。

a. Delegation to a named actor or group of actors

a. 指名されたアクターまたはアクターのグループへの委任

b. Advertising to a pool of actors for self-selection

b. 自己選択のためのアクターのプールへの告知

In either case, the assignment may be made based on a variety of criteria including, name, availability, skills, capacity, etc.

いずれの場合も、割り当ては、名前、空き状況、スキル、キャパシティなど、さまざまな基準に基づいて行われる場合があります。

Task Generating System:

タスク生成システム:

A system that creates and assigns tasks in response to some initiating event (task trigger). Process Logic defines task creation, while Task Assignment Rules determine task assignment. This system also tracks the status of tasks and will initiate further actions based upon the status. A Task Generating System can take many forms, such as a Business Process Management System, Project Management System, Bug Tracking System, and Building Control System. A Task Generating System may also be a human. In iCalendar terms the Task Generating System is the "Organizer".

何らかの起点となるイベント（タスクトリガー）に応じてタスクを作成し割り当てるシステム。タスクの作成はプロセスロジックが定義し、タスクの割り当てはタスク割り当てルールが決定します。このシステムはタスクのステータスも追跡し、そのステータスに基づいてさらなるアクションを開始します。タスク生成システムには、ビジネスプロセス管理システム、プロジェクト管理システム、バグ追跡システム、ビル制御システムなど、さまざまな形態がありえます。タスク生成システムは人間である場合もあります。iCalendarの用語では、タスク生成システムは "Organizer" です。

Task creation, assignment, and tracking coordinated by a human "Organizer" is a special case of a Task Generating System. In this case, Task Assignment Rules and Process Logic may be either explicit or tacit.

人間の "Organizer" が調整するタスクの作成、割り当て、追跡は、タスク生成システムの特殊なケースです。この場合、タスク割り当てルールとプロセスロジックは、明示的な場合も暗黙的な場合もあります。

Calendar and Scheduling System:

カレンダーおよびスケジューリングシステム:

A software system that stores, publishes, and synchronizes calendar data such as events, tasks, and journal entries for actors. In the context of tasks, this includes schedules (i.e., allocated time and availability to perform tasks) and task lists. A calendar and scheduling system typically consists of server and client software components.

アクターのために、イベント、タスク、ジャーナルエントリなどのカレンダーデータを保存、公開、同期するソフトウェアシステム。タスクの文脈では、これにはスケジュール（すなわち、タスクを実行するために割り当てられた時間と空き状況）とタスクリストが含まれます。カレンダーおよびスケジューリングシステムは、通常、サーバーとクライアントのソフトウェアコンポーネントで構成されます。

It is not within the scope of this document to specify how Process Logic or Task Assignment Rules are codified. Such logic and rules may be codified in a variety of ways, including conventional programming languages (e.g., C++ and Java) or process modeling languages (e.g., Business Process Model and Notation (BPMN) [BPMN]).

プロセスロジックやタスク割り当てルールをどのように体系化するかを規定することは、本文書の範囲外です。そのようなロジックやルールは、従来のプログラミング言語（例: C++ や Java）や、プロセスモデリング言語（例: Business Process Model and Notation (BPMN) [BPMN]）など、さまざまな方法で体系化できます。

2.2. Architecture Foundations
2.2. アーキテクチャの基盤

The key standards that enable interoperability between the logical elements of the architecture are iCalendar [RFC5545] and the associated protocols. Task and task status are represented by the "VTODO" calendar component. Protocols include, in particular, the iCalendar Transport-Independent Interoperability Protocol (iTIP) [RFC5546] for task assignment and scheduling and the Calendaring Extensions to WebDAV (CalDAV) [RFC4791] for client server communication.

アーキテクチャの論理要素間の相互運用性を可能にする主要な標準は、iCalendar [RFC5545] および関連プロトコルです。タスクとタスクのステータスは、"VTODO" カレンダーコンポーネントで表現されます。プロトコルには、特に、タスクの割り当てとスケジューリングのための iCalendar Transport-Independent Interoperability Protocol (iTIP) [RFC5546] と、クライアントサーバー間通信のための Calendaring Extensions to WebDAV (CalDAV) [RFC4791] があります。

Additionally, this specification uses definitions from "Support for iCalendar Relationships" [RFC9253]. The "LINK", "REFID", "RELATED-TO", and "CONCEPT" properties enable context and a rich set of relationships between tasks and other calendar components to be specified.

さらに、本仕様は「Support for iCalendar Relationships」[RFC9253] の定義を使用します。"LINK"、"REFID"、"RELATED-TO"、"CONCEPT" の各プロパティにより、タスクと他のカレンダーコンポーネントとの間のコンテキストや豊富な関係を指定できます。

3. タスク拡張

In order to support the task architecture described in Section 2, this document defines a number of extensions to iCalendar [RFC5545] in the following areas:

セクション2で説明したタスクアーキテクチャをサポートするために、本ドキュメントは次の分野で iCalendar [RFC5545] に対する複数の拡張を定義します。

Task Specification:

タスクの仕様：

ドメイン固有のタスクを指定する能力の改善。

Task Deadlines, Milestones, and Time Planning:

タスクの期限、マイルストーン、時間計画：

Clarification of deadlines and extension for task duration to support task time planning.

期限の明確化と、タスクの時間計画をサポートするためのタスク所要時間の拡張。

Task Scheduling and Assignment:

タスクのスケジューリングと割り当て：

Ensure support for common patterns of scheduling and assigning tasks.

タスクのスケジューリングと割り当てに関する一般的なパターンを確実にサポートすること。

Task Status Tracking:

タスクステータスの追跡：

Improved granularity in status tracking information and alerting task actors of pending or actual task status changes.

ステータス追跡情報の粒度の改善と、保留中または実際のタスクステータス変更のタスクアクターへの通知。

These extensions are supported mainly by additions to the properties and parameters used within the "VTODO" calendar component.

これらの拡張は主に、"VTODO" カレンダーコンポーネント内で使用されるプロパティとパラメータの追加によってサポートされます。

4. Task Specification
4. タスクの仕様

The specification of tasks must be semantically explicit in order for them to be managed within the context of a business process or project and understood by both humans and IT systems. The "VTODO" calendar component [RFC5545] only provides for simple ad hoc tasks or to-do lists and is therefore extended by this specification as follows:

タスクがビジネスプロセスやプロジェクトの文脈内で管理され、人間とITシステムの双方に理解されるためには、タスクの仕様が意味的に明示的でなければなりません。"VTODO" カレンダーコンポーネント [RFC5545] は、単純なアドホックタスクやToDoリストにしか対応していないため、本仕様では次のように拡張します。

Task Type:

タスクタイプ：

Explicitly what type of task is to be performed is identified.

実行すべきタスクの種類を明示的に識別します。

Task Context and Relationships:

タスクのコンテキストと関係：

How a specific task relates to other tasks and other objects that need to be understood for the effective execution of a task.

特定のタスクが、他のタスクや、タスクを効果的に実行するために理解しておく必要がある他のオブジェクトとどのように関係するか。

Task-Specific Data:

タスク固有のデータ：

The form and content of domain data provided as input to a task and/or that may be output from a task.

タスクへの入力として提供される、および/またはタスクから出力されうるドメインデータの形式と内容。

Organizer and Attendee:

オーガナイザーと出席者：

Recognizes that a task "Organizer" or "Attendee" can be an automated system.

タスクの "Organizer" や "Attendee" が自動化されたシステムであってもよいことを認めます。

4.1. Task Type
4.1. タスクタイプ

The "CONCEPT" property [RFC9253] is used to identify the type of task, for example:

"CONCEPT" プロパティ [RFC9253] は、タスクの種類を識別するために使用されます。例： 

   CONCEPT:http://example.com/task/delivery
4.2. Task Context and Relationships
4.2. タスクのコンテキストと関係

The "LINK" property [RFC9253] specifies a link to external information, which may provide context for the task. For example:

"LINK" プロパティ [RFC9253] は、タスクのコンテキストを提供しうる外部情報へのリンクを指定します。例： 

   LINK;LINKREL=describedby;VALUE=URI:
    mid:752142.141482.307E5@mx123.example.com

The external information may consist of data to be manipulated in performing the task.

外部情報は、タスクの実行時に操作されるデータで構成される場合があります。

The "LINK" property can be used to relate a domain-specific service to the task. For example, it might be a URI pointing to a web page where the status of the task can be directly manipulated.

"LINK" プロパティは、ドメイン固有のサービスをタスクに関連付けるために使用できます。たとえば、タスクのステータスを直接操作できるWebページを指すURIである場合があります。

Note: The link relations below are for illustration only.

注：以下のリンク関係は説明のみを目的としています。 

   LINK;LINKREL="vacation-system";VALUE=URI:
    http://example.com/vacation-approval?id=1234

Additionally, it might be used to link data specific to the task, for example, an electronic copy of a signature taken to confirm delivery of a package.

さらに、タスク固有のデータをリンクするために使用される場合もあります。たとえば、荷物の配達を確認するために受け取った署名の電子コピーです。 

   LINK;LINKREL="electronic-signature";VALUE=URI:
    http://example.com/delivery/sig1234.jpg

The "REFID" property [RFC9253] is used to identify a key used to group tasks by that key.

"REFID" プロパティ [RFC9253] は、そのキーによってタスクをグループ化するために使用されるキーを識別するために使用されます。 

   REFID:Manhattan

   REFID:1234567890

Extensions to the "RELATED-TO" property defined in [RFC9253] allow temporal relationships between tasks as found in project management to be specified as well as parent/child relationships and dependencies (DEPENDS-ON). Tasks ("VTODO" calendar components) may also be related to other calendar components, for example, a "VEVENT" calendar component used to block time to perform a task.

[RFC9253] で定義されている "RELATED-TO" プロパティの拡張により、プロジェクト管理に見られるタスク間の時間的関係に加え、親子関係や依存関係 (DEPENDS-ON) を指定できます。タスク ("VTODO" カレンダーコンポーネント) は、他のカレンダーコンポーネントとも関連付けることができます。たとえば、タスクを実行する時間を確保するために使用される "VEVENT" カレンダーコンポーネントです。

5. Task Deadlines, Milestones, and Time Planning
5. タスクの期限、マイルストーン、時間計画
5.1. Deadlines
5.1. 期限

Deadlines for starting and finishing a task are defined by the "DTSTART", "DUE", and "DURATION" properties. The "DTSTART" property represents the earliest start time for beginning work on a task. The "DUE" or "DTSTART" + "DURATION" properties represent the latest finish time for a task. Thus, these properties define a "window" within which a task has to be performed. However, [RFC5545] provides no way to indicate how long the task is expected to take. This document defines a new "ESTIMATED-DURATION" property, in Section 10.1, to allow the estimated time that a task should take to be specified separately from the deadlines for starting and finishing a task. This supports time planning by enabling calendar user agents to display when tasks should occur, which allows calendar users to visualize when tasks should be performed and to allocate time to them accordingly.

タスクの開始と終了の期限は、"DTSTART"、"DUE"、"DURATION" の各プロパティで定義されます。"DTSTART" プロパティは、タスクの作業を開始できる最も早い時刻を表します。"DUE"、または "DTSTART" + "DURATION" の各プロパティは、タスクの最も遅い終了時刻を表します。したがって、これらのプロパティは、タスクを実行しなければならない「ウィンドウ」を定義します。しかし、[RFC5545] には、タスクにどれくらいの時間がかかる見込みかを示す方法がありません。本ドキュメントは、タスクの開始と終了の期限とは別に、タスクにかかるべき見積もり時間を指定できるようにするため、セクション10.1で新しい "ESTIMATED-DURATION" プロパティを定義します。これにより、カレンダーユーザーエージェントがタスクを行うべき時期を表示できるようになり、時間計画がサポートされます。その結果、カレンダーユーザーは、タスクをいつ実行すべきかを視覚化し、それに応じて時間を割り当てることができます。

5.2. Milestones
5.2. マイルストーン

A task that has intermediary deadlines (i.e., milestones) MUST be expressed by child "VTODO" calendar components (i.e., subtasks associated with each of the milestones) in conjunction with the "RELATED-TO" property to relate the parent and child tasks.

中間の期限 (すなわちマイルストーン) を持つタスクは、親タスクと子タスクを関連付ける "RELATED-TO" プロパティとあわせて、子の "VTODO" カレンダーコンポーネント (すなわち各マイルストーンに対応するサブタスク) で表現しなければなりません (MUST)。

6. Task Scheduling and Assignment
6. タスクのスケジューリングと割り当て

Tasks are assigned to actors using one or more "ATTENDEE" properties [RFC5545] and/or one or more "PARTICIPANT" calendar components [RFC9073], as described in Section 7.4.

タスクは、セクション7.4で説明するとおり、1つ以上の "ATTENDEE" プロパティ [RFC5545] および/または1つ以上の "PARTICIPANT" カレンダーコンポーネント [RFC9073] を使用してアクターに割り当てられます。

Communication of task assignment or delegation to one or more actors who are allocated to a task by the "Organizer" is directly supported by iTIP, i.e., all included "ATTENDEE" properties in an iTIP "REQUEST" are expected to perform the task.

"Organizer" によってタスクに割り当てられた1つ以上のアクターへのタスク割り当てまたは委任の通知は、iTIPによって直接サポートされます。すなわち、iTIPの "REQUEST" に含まれるすべての "ATTENDEE" プロパティは、そのタスクを実行することが期待されます。

The offering or advertising of a task to one or more (potential) actors where only one or a subset of the candidates may accept the task will be addressed by a later specification.

1人以上の（潜在的な）アクターにタスクを提示または告知し、候補者のうち1人または一部だけがそのタスクを受け入れられるようにする方法については、今後の仕様で扱います。

7. Status Reporting
7. ステータス報告
7.1. Improved Granularity in Status Reporting Information
7.1. ステータス報告情報の粒度の改善

This document defines a new "VSTATUS" calendar component (see Section 12.1) that can be used to group related information about the status of the task. This might include information on why (the "REASON" property) and when (the "DTSTAMP" property) a status has changed. In addition, new status values are specified to provide for task suspension, failure, and preparation.

本書は、タスクのステータスに関する関連情報をまとめるために使用できる、新しい "VSTATUS" カレンダーコンポーネントを定義します（12.1節を参照）。これには、ステータスが変更された理由（"REASON" プロパティ）と時刻（"DTSTAMP" プロパティ）に関する情報を含めることができます。さらに、タスクの一時停止、失敗、準備を表す新しいステータス値を規定します。 

   BEGIN:VSTATUS
   STATUS:FAILED
   REASON:https://example.com/reason/delivery-failed
   SUBSTATE:ERROR
   DTSTAMP:20130212T120000Z
   COMMENT:Breakdown
   END:VSTATUS
7.2. Comments Associated to Reasons and Status Changes
7.2. 理由およびステータス変更に関連付けられたコメント

Multiple comments and reasons may have the same status. As situations change, further "VSTATUS" calendar components can be added to provide additional information.

複数のコメントや理由が同じステータスを持つ場合があります。状況が変化したときは、追加情報を提供するために、さらに "VSTATUS" カレンダーコンポーネントを追加できます。 

   CONCEPT:https://example.com/task/delivery
   BEGIN:VSTATUS
   STATUS:FAILED
   SUBSTATE:ERROR
   DTSTAMP:20220212T104900Z
   COMMENT:Out of time
   END:VSTATUS
   BEGIN:VSTATUS
   STATUS:FAILED
   COMMENT:Traffic Accident on E44
   REASON:https://example.com/reason/traffic
   DTSTAMP:20220212T110451Z
   END:VSTATUS
   BEGIN:VSTATUS
   STATUS:FAILED
   COMMENT:Arrived after office hours
   REASON:https://example.com/reason/closed
   DTSTAMP:20220212T180451Z
   END:VSTATUS

Note that the "VSTATUS" calendar component is not intended to be used as a history of changes to a task's properties. The purpose of the "VSTATUS" calendar component is only to document changes related to fulfilling the tasks.

"VSTATUS" カレンダーコンポーネントは、タスクのプロパティに対する変更の履歴として使用することを意図したものではない点に注意してください。"VSTATUS" カレンダーコンポーネントの目的は、タスクの遂行に関する変更を記録することだけです。

7.3. Updating the Overall Status
7.3. 全体ステータスの更新

Only the Task Organizer, or the server acting as the Organizer's proxy, may change or add "VSTATUS" calendar components and the "STATUS" property.

"VSTATUS" カレンダーコンポーネントと "STATUS" プロパティを変更または追加できるのは、タスクのオーガナイザー、またはオーガナイザーのプロキシとして動作するサーバーだけです。

The overall "VSTATUS" will be changed in response to incoming "Attendee" replies. Each change of the overall "VSTATUS" MUST be accompanied by a change to the STATUS.

全体の "VSTATUS" は、受信した "Attendee" の返信に応じて変更されます。全体の "VSTATUS" を変更するたびに、STATUS の変更を伴わなければなりません (MUST)。

Note there is no defined ordering of properties and components so the DTSTAMP property SHOULD be set for each "VSTATUS" component to preserve ordering.

プロパティおよびコンポーネントには定義された順序がないため、順序を保持するために、各 "VSTATUS" コンポーネントには DTSTAMP プロパティを設定すべきです (SHOULD)。

7.4. Relating Reason and Comments to "ATTENDEE" Property Status Changes
7.4. 理由とコメントの "ATTENDEE" プロパティのステータス変更への関連付け

The "PARTICIPANT" calendar component [RFC9073] can be used to provide additional information about why an "ATTENDEE" property's participation status has changed, by following the guidelines set out in Section 7.1 of [RFC9073]. The "COMMENT" property can also be used to include additional human-readable information about why the associated "STATUS" or "ATTENDEE" property changed. For example, if a driver failed to deliver a package because of a puncture, it might be expressed as

"PARTICIPANT" カレンダーコンポーネント [RFC9073] を使用すると、[RFC9073] の7.1節に示されたガイドラインに従って、"ATTENDEE" プロパティの参加ステータスが変更された理由に関する追加情報を提供できます。"COMMENT" プロパティを使用して、関連する "STATUS" プロパティまたは "ATTENDEE" プロパティが変更された理由に関する、人が読める追加情報を含めることもできます。たとえば、ドライバーがパンクのために荷物を配達できなかった場合、次のように表現できます。 

   ATTENDEE;PARTSTAT=FAILED:mailto:xxx@example.com
   ...
   BEGIN:PARTICIPANT
   CALENDAR-ADDRESS:mailto:xxx@example.com
   DTSTAMP:20130226T1104510Z
   REASON:https://example.com/reason/van-break-down
   COMMENT:Puncture
   END:PARTICIPANT
7.5. Task Alerts and Notifications
7.5. タスクのアラートと通知

Different requirements to alert or notify task actors of pending or actual task status changes are recognized:

保留中または実際のタスクステータスの変更について、タスクアクターに警告または通知するための、次のようなさまざまな要件が認識されています。

Alarms:

アラーム：

"VALARM" calendar components operate in the calendar user agent space to notify the task actor of a pending task state for a task they are assigned to or are interested in.

"VALARM" カレンダーコンポーネントは、カレンダーユーザーエージェントの領域で動作し、タスクアクターに、担当している、または関心を持っているタスクの保留中のタスク状態を通知します。

Current standards (such as [RFC9074]) indicate that "VALARM" calendar components SHOULD be removed from incoming data, and many systems in fact do so. In a task assignment scenario, it may be appropriate for the "Organizer" to be able to set alarms for the participants. A system implementing these standards may choose to preserve "VALARM" calendar components, but sending a task via some external service may result in their removal. This issue is not addressed by this specification.

現行の標準（[RFC9074] など）では、"VALARM" カレンダーコンポーネントは受信データから削除すべきです (SHOULD) とされており、実際に多くのシステムがそのようにしています。タスクの割り当てのシナリオでは、"Organizer" が参加者のアラームを設定できると適切な場合があります。これらの標準を実装するシステムは "VALARM" カレンダーコンポーネントを保持することを選択できますが、外部サービスを介してタスクを送信すると、それらが削除される場合があります。この問題は、本仕様では扱いません。

Escalations:

エスカレーション：

An escalation or notification to the "Attendee", "Organizer", or other task actor may be required if a deadline associated with a task is exceeded or for some other reason. Process Logic identifying when and who to propagate escalations is the responsibility of the Task Generating System, e.g., a BPMS.

タスクに関連付けられた期限を超過した場合やその他の理由がある場合には、"Attendee"、"Organizer"、またはその他のタスクアクターへのエスカレーションまたは通知が必要になることがあります。エスカレーションをいつ、誰に伝達するかを特定するプロセスロジックは、タスク生成システム（たとえば BPMS）の責任です。

Notifications:

通知：

13. CalDAV Support for Task Mode
13. タスクモードに対するCalDAVのサポート

The CalDAV [RFC4791] calendar access protocol allows clients and servers to exchange iCalendar data. With the introduction of the "TASK-MODE" property in this specification, different automated task management behaviors may be delegated to the server by the Task Organizer depending upon the value of "TASK-MODE".

CalDAV [RFC4791] カレンダーアクセスプロトコルにより、クライアントとサーバーはiCalendarデータを交換できます。本仕様で "TASK-MODE" プロパティが導入されたことで、"TASK-MODE" の値に応じて、さまざまな自動タスク管理の動作をタスクオーガナイザーがサーバーに委任できるようになります。

In order for a CalDAV client to know what task modes are available, a CalDAV server advertises a CALDAV:supported-task-mode-set WebDAV property on calendar home or calendar collections if it supports the use of the "TASK-MODE" property as described in this specification. The server can advertise a specific set of supported task modes by including one or more CALDAV:supported-task-mode XML elements within the CALDAV:supported-task-mode-set XML element.

CalDAVクライアントが利用可能なタスクモードを知るために、CalDAVサーバーは、本仕様で説明されている "TASK-MODE" プロパティの使用をサポートしている場合、カレンダーホームまたはカレンダーコレクション上でWebDAVプロパティ CALDAV:supported-task-mode-set をアドバタイズします。サーバーは、CALDAV:supported-task-mode-set XML要素の中に1つ以上のCALDAV:supported-task-mode XML要素を含めることで、サポートする特定のタスクモードの集合をアドバタイズできます。

If no CALDAV:supported-task-mode XML elements are included in the WebDAV property, then clients MUST assume the server does not support this specification. The client MAY attempt to store iCalendar data containing "TASK-MODE" elements but needs to be prepared for a failure response from the server.

WebDAVプロパティにCALDAV:supported-task-mode XML要素が1つも含まれていない場合、クライアントは、サーバーが本仕様をサポートしていないものとみなさなければなりません (MUST)。クライアントは "TASK-MODE" 要素を含むiCalendarデータの保存を試みてもよい (MAY) ですが、サーバーからの失敗応答に備える必要があります。

A server supporting this specification MUST return an HTTP 403 response with a DAV:error element containing a CALDAV:supported-task-mode XML element, if a client attempts to store iCalendar data with a "TASK-MODE" element value not supported by the server.

本仕様をサポートするサーバーは、クライアントがサーバーでサポートされていない "TASK-MODE" 要素の値を持つiCalendarデータを保存しようとした場合、CALDAV:supported-task-mode XML要素を含むDAV:error要素を伴うHTTP 403応答を返さなければなりません (MUST)。

It is possible for a "TASK-MODE" value to be present in calendar data on the server being accessed by a client that does not support the "TASK-MODE" property. It is expected that existing clients, unaware of "TASK-MODE", will fail gracefully by ignoring the calendar property.

"TASK-MODE" プロパティをサポートしないクライアントがアクセスするサーバー上のカレンダーデータに、"TASK-MODE" の値が存在する可能性があります。"TASK-MODE" を認識しない既存のクライアントは、このカレンダープロパティを無視することで、問題なく動作を継続すると想定されています。
