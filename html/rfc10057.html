A YANG Data Model for Traffic Engineering Tunnels, Label Switched Paths, and Interfaces

トラフィックエンジニアリングトンネル、ラベルスイッチパス、インターフェースのためのYANGデータモデル

Abstract

概要

This document defines a YANG data model for the provisioning and management of Traffic Engineering (TE) tunnels, Label Switched Paths (LSPs), and interfaces. The model covers data pertinent to TE tunnels, TE LSPs, and TE interfaces that are independent of any technology or data plane encapsulation. The model is divided into two YANG modules that address both device-specific and device-independent data, supporting configuration, operational state, Remote Procedure Calls (RPCs), and event notifications.

本ドキュメントは、トラフィックエンジニアリング (TE) トンネル、ラベルスイッチパス (LSP)、およびインターフェースのプロビジョニングと管理のためのYANGデータモデルを定義します。このモデルは、あらゆる技術やデータプレーンのカプセル化に依存しない、TEトンネル、TE LSP、TEインターフェースに関連するデータを扱います。モデルは、デバイス固有のデータとデバイスに依存しないデータの両方を扱う2つのYANGモジュールに分かれており、コンフィグレーション、運用状態、リモートプロシージャコール (RPC)、およびイベント通知をサポートします。

1. Introduction

1. はじめに

This document defines a YANG data model intended for the provisioning and management of point-to-point Traffic Engineering (TE) tunnels, Label Switched Paths (LSPs), and interfaces. The modeling of point-to-multipoint TE Tunnels [RFC4875] and Segment Routing (SR) Policies [RFC9256] falls outside the scope of this document.

本ドキュメントは、ポイントツーポイントのトラフィックエンジニアリング (TE) トンネル、ラベルスイッチパス (LSP)、およびインターフェースのプロビジョニングと管理を目的としたYANGデータモデルを定義します。ポイントツーマルチポイントのTEトンネル [RFC4875] およびSegment Routing (SR) ポリシー [RFC9256] のモデリングは、本ドキュメントの範囲外です。

The data model described herein is divided into two YANG modules. The "ietf-te" module contains generic, device-independent data, and the "ietf-te-device" module addresses device-specific data.

本ドキュメントで説明するデータモデルは、2つのYANGモジュールに分かれています。"ietf-te" モジュールは汎用的でデバイスに依存しないデータを含み、"ietf-te-device" モジュールはデバイス固有のデータを扱います。

This document outlines the high-level relationships between the YANG modules it defines and other external protocol YANG modules. The TE data model intentionally excludes data specific to any signaling protocol, such as RSVP-TE [RFC3209] [RFC3473] or SR [RFC8402] [RFC9256] with the expectation that such technology models will be defined in separate documents and will augment the TE model as needed.

本ドキュメントは、本ドキュメントが定義するYANGモジュールと、外部のプロトコルYANGモジュールとの間の高レベルの関係を概説します。TEデータモデルは、RSVP-TE [RFC3209] [RFC3473] やSR [RFC8402] [RFC9256] などのシグナリングプロトコルに固有のデータを意図的に除外しています。そのような技術のモデルは別のドキュメントで定義され、必要に応じてTEモデルを augment することが想定されています。

3. Design Considerations

3. 設計上の考慮事項

This document describes a YANG data model for TE tunnels, TE LSPs, and TE interfaces that are independent of any data plane technology. One of the design objectives is to allow specific data plane technology models to reuse the TE data model and possibly augment it with technology-specific data.

本ドキュメントは、データプレーン技術に依存しないTEトンネル、TE LSP、TEインターフェースのためのYANGデータモデルを説明します。設計目標の1つは、特定のデータプレーン技術のモデルがTEデータモデルを再利用し、場合によっては技術固有のデータでそれを augment できるようにすることです。

The elements of the TE data model, including TE Tunnels, LSPs, and interfaces, have leafs that identify the technology layer where they reside. For example, the LSP encoding type can identify the technology associated with a TE Tunnel or LSP.

TEトンネル、LSP、インターフェースを含むTEデータモデルの要素は、それらが属する技術レイヤを識別するリーフを持ちます。たとえば、LSPエンコーディングタイプにより、TEトンネルやLSPに関連する技術を識別できます。

Also, the TE data model does not cover signaling protocol data. The signaling protocols used to instantiate TE LSPs are outside the scope of this document and are expected to be covered by augmentations defined in other documents.

また、TEデータモデルはシグナリングプロトコルのデータを扱いません。TE LSPのインスタンス化に使用されるシグナリングプロトコルは本ドキュメントの範囲外であり、他のドキュメントで定義される augment によって扱われることが想定されています。

The following other design considerations are taken into account with respect to data organization:

データの構成に関して、次のその他の設計上の考慮事項が考慮されています。

* The device-independent TE data is defined in the "ietf-te" module and can be used to manage data off a device, such as a TE controller. When the model is used to manage a specific device, the model contains the TE Tunnels originating from the specific device. When the model is used to manage a TE controller, the 'tunnel' list contains all TE Tunnels and TE tunnel segments originating from devices that the TE controller manages.

* デバイスに依存しないTEデータは "ietf-te" モジュールで定義され、TEコントローラなど、デバイス外のデータの管理に使用できます。モデルが特定のデバイスの管理に使用される場合、モデルにはその特定のデバイスを起点とするTEトンネルが含まれます。モデルがTEコントローラの管理に使用される場合、'tunnel' リストには、そのTEコントローラが管理するデバイスを起点とするすべてのTEトンネルおよびTEトンネルセグメントが含まれます。

* The device-specific TE data is defined in the "ietf-te-device" module.

* デバイス固有のTEデータは "ietf-te-device" モジュールで定義されます。

* The TE interfaces in the "ietf-te-device" module are modeled as references to existing interfaces defined in the 'ietf-interfaces' YANG module [RFC8343]. This approach ensures consistency by leveraging standardized interface definitions, allowing TE-specific parameters to be associated with interfaces already defined elsewhere, rather than redefining interface structures within the TE module.

* "ietf-te-device" モジュールのTEインターフェースは、'ietf-interfaces' YANGモジュール [RFC8343] で定義された既存のインターフェースへの参照としてモデル化されます。このアプローチは、標準化されたインターフェース定義を活用することで一貫性を確保し、TEモジュール内でインターフェース構造を再定義するのではなく、他の場所で既に定義されているインターフェースにTE固有のパラメータを関連付けることを可能にします。

* Minimal elements in the model are designated as "mandatory" to allow freedom to vendors to adapt the data model to their specific product implementation.

* モデル内の "mandatory" に指定される要素は最小限にとどめられており、ベンダーがデータモデルを各自の製品実装に適合させる自由を確保しています。

* Suitable defaults are specified for all configurable elements.

* 設定可能なすべての要素に対して、適切なデフォルト値が指定されています。

* Where TE functions or features might be optional within the deployed TE network, the model declares them as optional.

* デプロイされたTEネットワーク内でTEの機能や特徴が任意である可能性がある場合、モデルはそれらをオプションとして宣言します。

* Some groupings defined in this document include 'default' statements, which can be problematic for use cases involving templates or profiling. This design does not conform to the guidelines specified in Section 4.13 of [RFC9907]. However, this deviation is intentional as these groupings are specifically tailored for use within the YANG modules defined in this document as well as in [PATH-COMP]. The customization ensures appropriate behavior and consistency across these related modules.

* 本ドキュメントで定義されるいくつかのgroupingには 'default' ステートメントが含まれており、テンプレートやプロファイリングを伴うユースケースでは問題となる可能性があります。この設計は [RFC9907] のセクション4.13で規定されているガイドラインに適合していません。しかし、これらのgroupingは、本ドキュメントで定義されるYANGモジュール内および [PATH-COMP] 内で使用するために特に調整されたものであるため、この逸脱は意図的なものです。このカスタマイズにより、これら関連するモジュール間で適切な動作と一貫性が確保されます。

4. Model Overview

4. モデルの概要

The data model defined in this document covers the core TE features that are commonly supported by different vendor implementations. The support of extended or vendor specific TE features is expected to be in either augmentations or deviations to this model that are defined in separate documents.

本ドキュメントで定義するデータモデルは、さまざまなベンダーの実装で一般的にサポートされているTEの中核機能を対象としています。拡張されたTE機能やベンダー固有のTE機能のサポートは、別のドキュメントで定義される本モデルのaugmentationまたはdeviationのいずれかで行われることが想定されています。

5. TE YANG Module

5. TE YANGモジュール

The TE YANG module "ietf-te" supports the management and operation of a TE network. This includes creating, modifying, and retrieving information about TE Tunnels, LSPs, and interfaces and their associated attributes, e.g., Administrative Groups (AGs), Shared Risk Link Groups (SRLGs), etc.

TE YANGモジュール "ietf-te" は、TEネットワークの管理と運用をサポートします。これには、TEトンネル、LSP、インターフェース、およびそれらに関連する属性（例：管理グループ (AG)、Shared Risk Link Group (SRLG) など）に関する情報の作成、変更、取得が含まれます。

5.1. Relationship Between TE Tunnel, LSP, and Path

TEモデルは、TEトンネル、TEパス、LSPといういくつかの中核的な構成要素を中心に構築されています。これらの概念は、モデルの構造と機能の中心となるものです。

TE Tunnel:

TEトンネル：

In this context, a TE tunnel represents a logical construct that defines an engineered connectivity service between two endpoints in the network, typically an ingress (source) and an egress (destination). A tunnel is characterized by its attributes (such as name, encoding, and constraints) and serves as the container for the forwarding resources used to realize the desired connectivity.

この文脈において、TEトンネルは、ネットワーク内の2つのエンドポイント（通常はイングレス（送信元）とイーグレス（宛先））間の、エンジニアリングされた接続サービスを定義する論理的な構成要素を表します。トンネルは、その属性（名前、エンコーディング、制約など）によって特徴付けられ、目的の接続性を実現するために使用される転送リソースのコンテナとして機能します。

TE Path:

TEパス：

A path refers to a specific sequence of nodes and links through the network that traffic will follow to traverse the TE tunnel from source to destination. A TE tunnel may have one or more associated TE paths, such as a primary TE path (the preferred path) and secondary TE paths (used for protection or restoration). Each path specifies the constraints, preferences, and optimization criteria that guide its computation and selection.

パスとは、トラフィックが送信元から宛先へTEトンネルを通過するためにたどる、ネットワーク内の特定のノードとリンクの並びを指します。TEトンネルには、1つ以上の関連するTEパスを持たせることができます。たとえば、プライマリTEパス（優先されるパス）や、セカンダリTEパス（保護または復旧に使用されるパス）などです。各パスは、その計算と選択を導く制約、選好、最適化基準を規定します。

LSP:

LSP:

An LSP is an actual, instantiated connection in the data plane that follows a computed TE path through the network. It is the result of signaling protocols (such as RSVP-TE or Segment Routing) setting up forwarding state along the TE path, enabling the tunnel to carry traffic.

LSPは、データプレーンにおける、ネットワークを通る計算済みのTEパスに従う、実際にインスタンス化された接続です。これは、シグナリングプロトコル（RSVP-TEやSegment Routingなど）がTEパスに沿って転送状態を設定し、トンネルがトラフィックを運べるようにした結果です。

The relationship among these concepts is as follows:

これらの概念間の関係は次のとおりです。

A TE tunnel is the high-level logical object that defines the desired connectivity and its properties. Each TE tunnel can have one or more TE paths, which define candidate or active routes through the network that may be used to realize the tunnel's connectivity, subject to certain constraints and preferences. For each TE path selected for use, one or more LSPs are instantiated in the network to realize the forwarding state necessary to carry traffic along the specified TE path.

TEトンネルは、目的の接続性とその特性を定義する、高レベルの論理オブジェクトです。各TEトンネルは1つ以上のTEパスを持つことができ、これらはネットワークを通る候補ルートまたはアクティブなルートを定義します。これらのルートは、特定の制約と選好に従って、トンネルの接続性を実現するために使用される場合があります。使用のために選択された各TEパスに対して、指定されたTEパスに沿ってトラフィックを運ぶために必要な転送状態を実現するよう、1つ以上のLSPがネットワーク内にインスタンス化されます。

In summary, a TE tunnel defines the service, a TE path defines how to achieve the service, and an LSP is the instantiated mechanism that actually provides the service in the forwarding plane.

要約すると、TEトンネルはサービスを定義し、TEパスはそのサービスを実現する方法を定義し、LSPは転送プレーンで実際にサービスを提供する、インスタンス化されたメカニズムです。

5.2.3. TE LSPs

5.2.3. TE LSP

The 'lsps' container includes the set of TE LSPs that have been instantiated. A TE LSP is identified by a 3-tuple ('tunnel-name', 'lsp-id', 'node').

'lsps' コンテナには、インスタンス化されたTE LSPの集合が含まれます。TE LSPは、3つ組 ('tunnel-name', 'lsp-id', 'node') で識別されます。

When the model is used to manage a specific device, the 'lsps' list contains all TE LSPs that traverse the device (including ingressing, transiting, and egressing the device).

このモデルが特定のデバイスの管理に使用される場合、'lsps' リストには、そのデバイスを通過するすべてのTE LSP（そのデバイスでイングレス、トランジット、イーグレスとなるものを含む）が含まれます。

When the model is used to manage a TE controller, the 'lsps' list contains the TE LSPs on devices managed by the controller that act as ingress, and may optionally include TE LSPs on devices managed by the controller that act as a transit or egress role.

このモデルがTEコントローラの管理に使用される場合、'lsps' リストには、コントローラが管理するデバイスのうちイングレスとして動作するデバイス上のTE LSPが含まれ、コントローラが管理するデバイスのうちトランジットまたはイーグレスの役割で動作するデバイス上のTE LSPを任意で含めてもかまいません。

The TE device YANG module "ietf-te-device" models data that is specific to managing a TE device. This module augments the TE YANG module.

TEデバイスYANGモジュール "ietf-te-device" は、TEデバイスの管理に固有のデータをモデル化します。このモジュールは、TE YANGモジュールをaugmentします。

6.1. Module Structure

6.1. モジュール構造

The "ietf-te-device" module defines the configuration and operational state data that is specific to the device, including those related to the TE subsystem, tunnels, LSPs, and interfaces.

"ietf-te-device" モジュールは、TEサブシステム、トンネル、LSP、インターフェースに関するものを含め、デバイスに固有のコンフィグレーションデータおよび運用状態データを定義します。

6.1.1. TE Device Globals, Tunnels, and LSPs

6.1.1. TEデバイスのグローバル、トンネル、LSP

The "ietf-te-device" module augments the TE YANG module "ietf-te" at the 'globals', 'tunnels', and 'lsps' levels to include the device-specific configurations and operational state.

"ietf-te-device" モジュールは、TE YANGモジュール "ietf-te" を 'globals'、'tunnels'、'lsps' の各レベルで augment し、デバイス固有のコンフィグレーションと運用状態を追加します。

       +--rw lsp-cleanup-interval?        uint32

       +--rw path-invalidation-action?    identityref

       |  +--ro time-to-install?   uint32
       |  +--ro time-to-destroy?   uint32
       +--ro downstream-info
       |     ..
       +--ro upstream-info
             ..

The following is the description of the augmented data at each level.

以下は、各レベルで augment されるデータの説明です。

Global Timers (Augmenting /te:te/te:globals):

グローバルタイマー (/te:te/te:globals を augment):

These are device-specific global configuration parameters related to LSP timers, applied system-wide.

これらは、LSPタイマーに関連するデバイス固有のグローバルなコンフィグレーションパラメータであり、システム全体に適用されます。

lsp-install-interval:

lsp-install-interval:

An optional leaf that specifies the delay time, in seconds, before a newly provisioned LSP is installed into the forwarding plane to carry traffic.

新たにプロビジョニングされたLSPが、トラフィックを運ぶために転送プレーンにインストールされるまでの遅延時間を秒単位で指定する、オプションのleafです。

lsp-cleanup-interval:

lsp-cleanup-interval:

An optional leaf that specifies the delay time, in seconds, before an LSP is completely removed from the system after it is no longer in use.

LSPが使用されなくなってから、システムから完全に削除されるまでの遅延時間を秒単位で指定する、オプションのleafです。

lsp-invalidation-interval:

lsp-invalidation-interval:

An optional leaf that specifies the delay time, in seconds, during which a TE LSP's path is considered invalid before any corrective action is taken.

何らかの是正措置が取られるまでの間、TE LSPのパスが無効とみなされる遅延時間を秒単位で指定する、オプションのleafです。

Tunnel Device-Dependent Attributes (Augmenting /te:te/te:tunnels/ te:tunnel):

トンネルのデバイス依存属性 (/te:te/te:tunnels/te:tunnel を augment):

These are device-specific configuration parameters that apply to individual TE Tunnels:

これらは、個々のTEトンネルに適用されるデバイス固有のコンフィグレーションパラメータです。

path-invalidation-action:

path-invalidation-action:

An optional identityref that specifies the action to be taken when a TE Tunnel's path is deemed invalid (e.g., tear down, recompute).

TEトンネルのパスが無効と判断されたときに取るべき動作 (例: tear down、再計算) を指定する、オプションのidentityrefです。

lsp-install-interval:

lsp-install-interval:

An optional leaf that specifies the delay time, in seconds, for this specific TE Tunnel before its LSPs are installed into the forwarding plane. This value can override the global lsp-install-interval.

この特定のTEトンネルのLSPが転送プレーンにインストールされるまでの遅延時間を秒単位で指定する、オプションのleafです。この値は、グローバルな lsp-install-interval を上書きできます。

lsp-cleanup-interval:

lsp-cleanup-interval:

An optional leaf that specifies the delay time, in seconds, for this specific TE Tunnel before its LSPs are cleaned up. This value can override the global lsp-cleanup-interval.

この特定のTEトンネルのLSPがクリーンアップされるまでの遅延時間を秒単位で指定する、オプションのleafです。この値は、グローバルな lsp-cleanup-interval を上書きできます。

lsp-invalidation-interval:

lsp-invalidation-interval:

An optional leaf that specifies the delay time, in seconds, for this specific TE Tunnel during which its path is considered invalid before action is taken. This value can override the global lsp-invalidation-interval.

この特定のTEトンネルについて、アクションが取られるまでの間、そのパスが無効とみなされる遅延時間を秒単位で指定する、オプションのleafです。この値は、グローバルな lsp-invalidation-interval を上書きできます。

LSP Device-Dependent State (Augmenting /te:te/te:lsps/te:lsp):

LSPのデバイス依存状態 (/te:te/te:lsps/te:lsp を augment):

These are read-only operational state parameters providing device-specific details for individual LSPs:

これらは、個々のLSPに関するデバイス固有の詳細を提供する、読み取り専用の運用状態パラメータです。

lsp-timers:

lsp-timers:

A container that holds various timer-related operational state for an LSP, applicable primarily to ingress LSPs.

LSPのタイマー関連の各種運用状態を保持するコンテナです。主にイングレスLSPに適用されます。

uptime:

uptime:

An optional leaf that indicates the total time, in seconds, that the LSP has been operational.

LSPが稼働している合計時間を秒単位で示す、オプションのleafです。

time-to-install:

time-to-install:

An optional leaf that indicates the remaining time, in seconds, for a new LSP to be fully instantiated and ready to carry traffic.

新しいLSPが完全にインスタンス化され、トラフィックを運べる状態になるまでの残り時間を秒単位で示す、オプションのleafです。

time-to-destroy:

time-to-destroy:

An optional leaf that indicates the remaining time, in seconds, before an existing LSP is torn down.

既存のLSPが tear down されるまでの残り時間を秒単位で示す、オプションのleafです。

downstream-info:

downstream-info:

A container that holds information about the downstream neighbor and label for the LSP, applicable when the LSP is not at its egress.

LSPのダウンストリームのネイバーとラベルに関する情報を保持するコンテナです。LSPがイーグレスにない場合に適用されます。

upstream-info:

upstream-info:

A container that holds information about the upstream neighbor and label for the LSP, applicable when the LSP is not at its ingress.

LSPのアップストリームのネイバーとラベルに関する情報を保持するコンテナです。LSPがイングレスにない場合に適用されます。

The main elements under the interfaces container are:

interfaces コンテナの下にある主な要素は次のとおりです。

threshold-type:

threshold-type:

An optional enumeration that specifies the type of thresholding mechanism used for flooding bandwidth updates for all TE interfaces on the device. Options include 'delta' (flooding on a change greater than a specified delta) or 'threshold-crossed' (flooding when bandwidth crosses a defined threshold).

デバイス上のすべてのTEインターフェースについて、帯域幅の更新をフラッディングする際に使用するしきい値メカニズムの種類を指定する、任意の列挙型です。選択肢には、'delta'（指定されたデルタより大きな変化があったときにフラッディングする）と 'threshold-crossed'（帯域幅が定義されたしきい値を越えたときにフラッディングする）があります。

delta-percentage:

delta-percentage:

An optional percentage value, used when threshold-type is 'delta', indicating the change in reservable bandwidth that triggers an IGP update for all TE interfaces.

threshold-type が 'delta' のときに使用される、任意のパーセンテージ値です。すべてのTEインターフェースについて、IGPの更新を引き起こす予約可能な帯域幅の変化量を示します。

threshold-specification:

threshold-specification:

An optional enumeration, used when threshold-type is 'threshold-crossed', to define whether a single set of 'mirrored-up-down' thresholds or separate 'separate-up-down' thresholds are used for increasing and decreasing bandwidth. This applies globally to all TE interfaces.

threshold-type が 'threshold-crossed' のときに使用される、任意の列挙型です。帯域幅の増加時と減少時に、単一の 'mirrored-up-down' しきい値の組を使用するか、別々の 'separate-up-down' しきい値を使用するかを定義します。これはすべてのTEインターフェースにグローバルに適用されます。

up-thresholds:

up-thresholds:

A list of percentage values, used with 'separate-up-down' thresholding, that define the points at which bandwidth updates are triggered when the reservable bandwidth is increasing across all TE interfaces.

'separate-up-down' しきい値方式で使用されるパーセンテージ値のリストです。すべてのTEインターフェースにわたり、予約可能な帯域幅が増加しているときに帯域幅の更新が引き起こされる点を定義します。

down-thresholds:

down-thresholds:

A list of percentage values, used with 'separate-up-down' thresholding, that define the points at which bandwidth updates are triggered when the reservable bandwidth is decreasing across all TE interfaces.

'separate-up-down' しきい値方式で使用されるパーセンテージ値のリストです。すべてのTEインターフェースにわたり、予約可能な帯域幅が減少しているときに帯域幅の更新が引き起こされる点を定義します。

up-down-thresholds:

up-down-thresholds:

A list of percentage values, used with 'mirrored-up-down' thresholding, that define the points at which bandwidth updates are triggered for both increasing and decreasing reservable bandwidth across all TE interfaces.

'mirrored-up-down' しきい値方式で使用されるパーセンテージ値のリストです。すべてのTEインターフェースにわたり、予約可能な帯域幅の増加と減少の両方について、帯域幅の更新が引き起こされる点を定義します。

interface:

interface:

A list of individual TE interfaces configured on the device. Each entry represents a network interface enabled for Traffic Engineering and contains its specific attributes and state. A TE interface is identified by the 'name' leaf, which references an existing network interface on the device.

デバイス上に設定された個々のTEインターフェースのリストです。各エントリは、トラフィックエンジニアリングが有効化されたネットワークインターフェースを表し、そのインターフェース固有の属性と状態を含みます。TEインターフェースは 'name' リーフによって識別され、このリーフはデバイス上に存在するネットワークインターフェースを参照します。

name:

name:

A leaf that uniquely identifies the TE interface, referencing an existing network interface.

既存のネットワークインターフェースを参照して、TEインターフェースを一意に識別するリーフです。

te-metric:

te-metric:

An optional leaf that holds the TE metric value associated with this specific interface, used during path computation.

この特定のインターフェースに関連付けられたTEメトリック値を保持する任意のリーフで、パス計算時に使用されます。

admin-group-type:

admin-group-type:

A choice node that allows configuring administrative groups for the interface using either direct values or named references.

直接の値または名前付き参照のいずれかを使用して、インターフェースの管理グループを設定できるようにする choice ノードです。

value-admin-groups:

value-admin-groups:

A choice for defining administrative groups using direct bitmask values.

直接のビットマスク値を使用して管理グループを定義するための choice です。

named-admin-groups:

named-admin-groups:

A list of named administrative groups applied to this TE interface, referencing globally defined named administrative groups.

このTEインターフェースに適用される名前付き管理グループのリストで、グローバルに定義された名前付き管理グループを参照します。

srlg-type:

srlg-type:

A choice node that allows configuring SRLGs for the interface using either direct values or named references.

直接の値または名前付き参照のいずれかを使用して、インターフェースのSRLGを設定できるようにする choice ノードです。

value-srlgs:

value-srlgs:

A list of direct SRLG values that this link is a part of.

このリンクが属する、直接のSRLG値のリストです。

named-srlgs:

named-srlgs:

A list of named SRLGs applied to this interface, referencing globally defined named SRLGs.

このインターフェースに適用される名前付きSRLGのリストで、グローバルに定義された名前付きSRLGを参照します。

threshold-type:

threshold-type:

An optional enumeration, similar to the global threshold-type, but specifically for this individual TE interface, allowing per-interface override of the global bandwidth flooding behavior.

グローバルな threshold-type に似ていますが、この個々のTEインターフェース専用の任意の列挙型です。グローバルな帯域幅フラッディング動作をインターフェースごとに上書きできます。

delta-percentage:

delta-percentage:

An optional percentage value, specific to this interface, used when its threshold-type is 'delta'.

このインターフェース固有の任意のパーセンテージ値で、このインターフェースの threshold-type が 'delta' のときに使用されます。

threshold-specification:

threshold-specification:

An optional enumeration, specific to this interface, used when its threshold-type is 'threshold-crossed'.

このインターフェース固有の任意の列挙型で、このインターフェースの threshold-type が 'threshold-crossed' のときに使用されます。

up-thresholds:

up-thresholds:

A list of percentage values, specific to this interface, used with 'separate-up-down' thresholding for increasing bandwidth.

このインターフェース固有のパーセンテージ値のリストで、帯域幅の増加に対する 'separate-up-down' しきい値方式で使用されます。

down-thresholds:

down-thresholds:

A list of percentage values, specific to this interface, used with 'separate-up-down' thresholding for decreasing bandwidth.

このインターフェースに固有の、帯域幅の減少に対して 'separate-up-down' しきい値処理で使用されるパーセンテージ値のリストです。

up-down-thresholds:

up-down-thresholds:

A list of percentage values, specific to this interface, used with 'mirrored-up-down' thresholding for both increasing and decreasing bandwidth.

このインターフェースに固有の、帯域幅の増加と減少の両方に対して 'mirrored-up-down' しきい値処理で使用されるパーセンテージ値のリストです。

switching-capabilities:

switching-capabilities:

A list of switching capabilities supported by this interface.

このインターフェースがサポートするスイッチング能力のリストです。

switching-capability:

switching-capability:

An identityref indicating a specific switching capability (e.g., Packet, Lambda, Fiber).

特定のスイッチング能力（例：Packet、Lambda、Fiber）を示す identityref です。

encoding:

encoding:

An optional identityref indicating the LSP encoding type supported by this capability on the interface.

インターフェース上のこの能力がサポートする LSP エンコーディングタイプを示す、オプションの identityref です。

te-advertisements-state:

te-advertisements-state:

A read-only container that provides operational state information related to how this TE interface's attributes are advertised.

このTEインターフェースの属性がどのようにアドバタイズされるかに関する運用状態情報を提供する、読み取り専用のコンテナです。

flood-interval:

flood-interval:

An optional leaf indicating the configured periodic flooding interval for this interface.

このインターフェースに対して設定された定期的なフラッディング間隔を示す、オプションのリーフです。

last-flooded-time:

last-flooded-time:

An optional leaf showing the time elapsed since the last advertisement flood for this interface.

このインターフェースの直近のアドバタイズメントのフラッディングからの経過時間を示す、オプションのリーフです。

next-flooded-time:

next-flooded-time:

An optional leaf showing the time remaining until the next scheduled advertisement flood for this interface.

このインターフェースの次回予定されているアドバタイズメントのフラッディングまでの残り時間を示す、オプションのリーフです。

last-flooded-trigger:

last-flooded-trigger:

An optional enumeration indicating the event that triggered the last advertisement flood (e.g., link-up, bandwidth-change, periodic-timer).

直近のアドバタイズメントのフラッディングを引き起こしたイベント（例：link-up、bandwidth-change、periodic-timer）を示す、オプションの列挙型です。

advertised-level-areas:

advertised-level-areas:

A list of IGP level-areas in which this TE interface's link state information is advertised.

このTEインターフェースのリンク状態情報がアドバタイズされる IGP のレベルエリアのリストです。

9. Security Considerations

9. セキュリティに関する考慮事項

The "ietf-te" and "ietf-te-device" YANG modules define a data model that is designed to be accessed via YANG-based management protocols, such as the Network Configuration Protocol (NETCONF) [RFC6241] and RESTCONF [RFC8040]. These YANG-based management protocols (1) have to use a secure transport layer (e.g., Secure Shell (SSH) [RFC6242], TLS [RFC9846], and QUIC [RFC9000]) and (2) have to use mutual authentication.

"ietf-te" および "ietf-te-device" YANGモジュールは、Network Configuration Protocol (NETCONF) [RFC6241] や RESTCONF [RFC8040] などのYANGベースの管理プロトコルを介してアクセスされるように設計されたデータモデルを定義します。これらのYANGベースの管理プロトコルは、(1) セキュアなトランスポート層 (例: Secure Shell (SSH) [RFC6242]、TLS [RFC9846]、QUIC [RFC9000]) を使用しなければならず、かつ (2) 相互認証を使用しなければなりません。

The Network Configuration Access Control Model (NACM) [RFC8341] provides the means to restrict access for particular NETCONF or RESTCONF users to a preconfigured subset of all available NETCONF or RESTCONF protocol operations and content.

Network Configuration Access Control Model (NACM) [RFC8341] は、特定のNETCONFユーザまたはRESTCONFユーザによるアクセスを、利用可能なすべてのNETCONFプロトコル操作またはRESTCONFプロトコル操作およびコンテンツのうち、あらかじめ設定された一部に制限する手段を提供します。

There are a number of data nodes defined in these YANG modules that are writable/creatable/deletable (i.e., "config true", which is the default). All writable data nodes are likely to be sensitive or vulnerable in some network environments. Write operations (e.g., edit-config) and delete operations to these data nodes without proper protection or authentication can have a negative effect on network operations. The following subtrees and data nodes have particular sensitivities/vulnerabilities:

これらのYANGモジュールには、書き込み可能/作成可能/削除可能な (すなわち "config true" であり、これがデフォルトです) データノードが多数定義されています。書き込み可能なすべてのデータノードは、ネットワーク環境によっては機微であるか脆弱である可能性があります。適切な保護や認証なしにこれらのデータノードに対して書き込み操作 (例: edit-config) や削除操作を行うと、ネットワーク運用に悪影響を及ぼす可能性があります。次のサブツリーとデータノードには、特に機微性/脆弱性があります。
