Clarifying Segment Routing over IPv6 (SRv6) Segment Identifier (SID) List Processing

RFC 10094 - IPv6上のセグメントルーティング (SRv6) のセグメント識別子 (SID) リスト処理の明確化

Abstract

概要

Segment Routing over IPv6 (SRv6) is the instantiation of Segment Routing (SR) on the IPv6 data plane. Segments are indicated by Segment Identifiers (SIDs). SRv6 utilizes the Segment Routing Header (SRH), an IPv6 extension header that includes a SID list indicating the sequence of segments and any additional processing to be performed.

IPv6上のセグメントルーティング (SRv6) は、セグメントルーティング (SR) をIPv6データプレーン上で実現したものです。セグメントはセグメント識別子 (SID) によって示されます。SRv6はセグメントルーティングヘッダー (SRH) を利用します。SRHは、セグメントの順序と実行すべき追加の処理を示すSIDリストを含むIPv6拡張ヘッダーです。

This document updates RFC 8754 by clarifying the processing of SID list entries. It does not change any elements of the SRv6 architecture.

この文書はRFC 8754を更新し、SIDリストのエントリの処理を明確化します。SRv6アーキテクチャの要素は何も変更しません。

1. Introduction

1. はじめに

The Segment Routing (SR) architecture is specified in [RFC8402]. SR forwards packets along a series of segments, and it may perform additional segment-specific processing on packets. Segments are indicated by Segment Identifiers (SIDs).

セグメントルーティング (SR) アーキテクチャは [RFC8402] で規定されています。SRは一連のセグメントに沿ってパケットを転送し、パケットに対してセグメント固有の追加処理を実行することがあります。セグメントはセグメント識別子 (SID) によって示されます。

The mechanisms to achieve Segment Routing over IPv6 (SRv6) include the use of the Segment Routing Header (SRH) [RFC8754], an IPv6 extension header that includes a SID list indicating the sequence of segments and any additional processing to be performed.

IPv6上のセグメントルーティング (SRv6) を実現する仕組みには、セグメントルーティングヘッダー (SRH) [RFC8754] の使用が含まれます。SRHは、セグメントの順序と実行すべき追加の処理を示すSIDリストを含むIPv6拡張ヘッダーです。

This document updates [RFC8754] by clarifying the processing of SID list entries. It does not change any elements of the SRv6 architecture.

この文書は [RFC8754] を更新し、SIDリストのエントリの処理を明確化します。SRv6アーキテクチャの要素は何も変更しません。

2. Clarification

2. 明確化

The SRH is processed per Section 4 of [RFC8754]. One objective of that processing is to determine the value to place in the Destination Address field of the IPv6 packet. To this end, the next entry in the SID list in the SRH is processed and mapped to the value to place in the Destination Address field.

SRHは [RFC8754] のセクション4に従って処理されます。この処理の目的の1つは、IPv6パケットのDestination Addressフィールドに設定する値を決定することです。そのために、SRH内のSIDリストの次のエントリが処理され、Destination Addressフィールドに設定する値にマッピングされます。

The value placed in the 128-bit Destination Address field of an IPv6 packet header needs to be a routable IPv6 address since that is required for forwarding the packet.

IPv6パケットヘッダーの128ビットのDestination Addressフィールドに設定する値は、パケットの転送に必要となるため、ルーティング可能なIPv6アドレスである必要があります。

Note that entries in the SID list do not need to be fully formed IPv6 addresses that are copied directly to the Destination Address field of the IPv6 packet. The mapping from SID list entry to the destination address could be a direct copy (the SID list contains a list of IPv6 addresses) or could involve a more complex function.

SIDリストのエントリは、IPv6パケットのDestination Addressフィールドへ直接コピーされる完全な形式のIPv6アドレスである必要はない点に注意してください。SIDリストのエントリから宛先アドレスへのマッピングは、直接のコピー (SIDリストがIPv6アドレスのリストを含む場合) である場合もあれば、より複雑な関数を伴う場合もあります。

An example of such a function is shown in [RFC9800], where a REPLACE-CSID compressed SID is expanded to be placed in the Destination Address field. Note that [RFC9800] formally updates [RFC8754] to allow this mapping function -- such an update would not have been needed if this document had already existed.

このような関数の例は [RFC9800] に示されており、REPLACE-CSID圧縮SIDが展開されてDestination Addressフィールドに設定されます。[RFC9800] はこのマッピング関数を許可するために [RFC8754] を正式に更新していますが、この文書がすでに存在していたならば、そのような更新は必要なかったはずである点に注意してください。

3. Updates to RFC 8754

3. RFC 8754の更新

3.1. Segments Left in Section 2 of RFC 8754

3.1. RFC 8754のセクション2のSegments Left

The definition of the Segments Left field of the SRH is presented as:

SRHのSegments Leftフィールドの定義は次のように示されています。

Segments Left:

Segments Left:

Defined in [RFC8200], Section 4.4.

[RFC8200] のセクション4.4で定義されています。

This is clarified by Erratum ID 7102 [Err7102]. This clarification is included in this update for completeness. The new text reads:

これはErratum ID 7102 [Err7102] によって明確化されています。この明確化は、完全を期すために今回の更新に含められています。新しいテキストは次のとおりです。

Segments Left:

Segments Left:

Defined in [RFC8200], Section 4.4. Specifically, for the SRH, the number of unprocessed 128-bit entries in the Segment List.

[RFC8200] のセクション4.4で定義されています。具体的には、SRHにおいては、Segment List内の未処理の128ビットエントリの数です。

3.3. HMAC Processing in Section 2.1.2.1 of RFC 8754

3.3. RFC 8754のセクション2.1.2.1のHMAC処理

In describing the Hashed Message Authentication Code (HMAC) processing, the text in [RFC8754] says that HMAC verification checks that the destination address of the packet matches that indicated by the next entry in the Segment List.

ハッシュ化メッセージ認証コード (HMAC) の処理を説明する際、[RFC8754] のテキストは、HMACの検証ではパケットの宛先アドレスがSegment Listの次のエントリで示されるアドレスと一致することを確認する、としています。

* HMAC Segments Left is less than or equal to Last Entry, and the destination address is equal to Segment List[Segments Left].

* HMAC Segments LeftがLast Entry以下であり、かつ宛先アドレスがSegment List[Segments Left]と等しい。

This is updated to allow a nondirect mapping from the Segment List entry to the destination address as follows:

これは、Segment Listのエントリから宛先アドレスへの直接でないマッピングを許可するために、次のように更新されます。

* HMAC Segments Left is less than or equal to the Last Entry, and the destination address is equal to the address created by mapping from Segment List[Segments Left].

* HMAC Segments LeftがLast Entry以下であり、かつ宛先アドレスがSegment List[Segments Left]からのマッピングによって作成されたアドレスと等しい。

Further, in describing the concatenation of information to generate the text field input to the HMAC computation, Section 2.1.2.1 of [RFC8754] says:

さらに、HMAC計算へのテキスト入力を生成するための情報の連結を説明する際、[RFC8754] のセクション2.1.2.1は次のように述べています。

* SRH: All addresses in the Segment List (variable octets)

* SRH: Segment List内のすべてのアドレス (可変長オクテット)

This is updated as follows to indicate that Segment List entries are not necessarily IPv6 addresses.

これは、Segment Listのエントリが必ずしもIPv6アドレスではないことを示すために、次のように更新されます。

* SRH: All entries in the Segment List (variable octets)

* SRH: Segment List内のすべてのエントリ (可変長オクテット)

3.4. ICMP Processing in Section 5.4 of RFC 8754

3.4. RFC 8754のセクション5.4のICMP処理

The method for deriving the destination address of the invoking packet in [RFC8754] reads as:

[RFC8754] における、呼び出し元パケットの宛先アドレスを導出する方法は、次のとおりです。

* The SID at Segment List[0] may be used as the destination address of the invoking packet.

* Segment List[0] のSIDを、呼び出し元パケットの宛先アドレスとして使用してもよい。

To allow for the zeroth entry in the Segment List to be mapped rather than copied to a destination address, this is updated to:

Segment Listの0番目のエントリを、宛先アドレスにコピーするのではなくマッピングできるようにするために、これは次のように更新されます。

* The SID at Segment List[0] may be mapped to derive the destination address of the invoking packet.

* Segment List[0] のSIDをマッピングして、呼び出し元パケットの宛先アドレスを導出してもよい。

4. Operational Considerations

4. 運用上の考慮事項

This document does not change any elements of the SRv6 architecture and, as such, it makes no change to the operational procedures or management tools of SR.

この文書はSRv6アーキテクチャの要素を何も変更しないため、SRの運用手順や管理ツールにも変更を加えません。

In clarifying the nature of SID list processing, this document also clarifies the nature of SID list entries. Operational and management tools that examine the SID list in a packet need to be aware of the nature of those entries in order to offer maximal clarity to the users of those tools.

この文書はSIDリスト処理の性質を明確化するとともに、SIDリストのエントリの性質も明確化します。パケット内のSIDリストを調べる運用・管理ツールは、これらのツールの利用者に最大限の明確さを提供するために、エントリの性質を認識しておく必要があります。

5. Security Considerations

5. セキュリティに関する考慮事項

This document makes no changes to the security properties of SRv6. See [SRv6-SECURITY], [RFC8402], and [RFC8754] for more discussion of SRv6 security.

この文書はSRv6のセキュリティ特性を何も変更しません。SRv6のセキュリティに関する詳細は、[SRv6-SECURITY]、[RFC8402]、[RFC8754] を参照してください。

Note that describing the SID list entries as being mapped to the destination address of a packet enables potential additional security mechanisms, such as encrypting the SID list.

SIDリストのエントリがパケットの宛先アドレスにマッピングされるものとして説明することで、SIDリストの暗号化など、追加のセキュリティ機構を導入できる可能性が生まれる点に注意してください。
