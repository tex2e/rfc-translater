## 残った欠陥について

**E001 が 0 でも識別子が全て正しいわけではありません。** 自動判定できない分は
W009 として別に計上しています（1,423件）。指標を良く見せないための分離です。

W009 は原文内で同じ綴りが複数の表記で現れるケースです。SMIやC APIの慣習で
以下のように併存します。

```
natInterfaceEntry OBJECT-TYPE SYNTAX NatInterfaceEntry ...
CMSG_DATA() ... what is called the cmsg_data[] member ...
```

訳文には壊れた表記が1つしかないため、どちらに復元すべきか機械的には決定できません。
誤修正を出さないため自動変換の対象外とし、人手またはAIの判断に委ねています。

**W006 の残り 3,443 件は機械変換できない見出しです。** 内訳:

- サ変動詞でないもの — 「オプションを含めます」「曖昧性を乱します」
  （含める・乱すは五段/下一段動詞。体言化に語彙判断が要る）
- 主題の「は」を含む文 — 「パディングフレームは輻輳ウィンドウを消費します」
  （体言止めにすると「Xは〜の消費」となり非文になるため除外）
- 「〜です」「〜できます」で終わるもの — 「共通の語彙が必要です」
  （「共通の語彙の必要性」のような書き換えは意味理解が必要）
- 主語マーカー「が」が述語を失うもの — 「同等のアルゴリズムが許可されています」
  （「〜が許可」は体言止めではなく係り先のない断片になるため変換しない）

### E002 の誤検知について（重要）

当初 E002 は 365 件でしたが、**うち 40 件は linter の誤検知**でした。
原因は2つで、いずれも修正済みです。

1. **`MUST not` のような小文字表記を見落としていた。** RFC本文では
   `MUST NOT` が `MUST not` と書かれることがあります。これを「MUST（必須）」と
   誤認し、訳文の「〜してはなりません」を誤訳として報告していました。
2. **肯定形キーワード + 原文の否定表現を考慮していなかった。**
   `MUST be absent` / `MUST signal X but not execute Y` のような文では、
   訳文が「〜してはなりません」になるのが正しい訳です。

この種の誤検知は、`MUST/SHALL/SHOULD` に対して訳文が禁止・非推奨相当だった
55件のうち **47件（85%）** を占めていました。

**E002 は自動修正してはいけません。** 「MUST reject」を「受け入れてはなりません」と
訳すような正しい言い換えが存在するため、置換先は文ごとに読んで決める必要があります。
残る 325 件は人手またはAIレビューの対象です。

## 次の優先順位

1. **E002 325件** — 最優先。実装可否の誤判断に直結します。自動修正は不可。
   着手順は次のコマンドで生成します（被引用数で重み付けした優先順リスト）。

   ```sh
   python3 tools/rank_rfcs.py --scan          # 帯ごとなら --dir 8000 など
   python3 tools/rank_rfcs.py --report --check E002 --limit 30
   ```

   修正が進むと順位が変わるため、リストはファイルに固定せず都度生成します。
2. **W003 73,880件** — 大半は `MUST` を「〜する必要があります」と訳したもの。
   件数が最大ですが、E002と同じ理由で単純な一括置換は危険です。どの節の
   キーワードに対応するかを読まないと決まらないため、方針決定が必要です。
3. **W006 残り3,443件 / W009 1,423件** — 語彙判断が要るためAIレビュー向き。
4. **W005 残り3件** — 「取り組んだ」「運んだ」のような五段動詞の過去形。
   「んだ」からは辞書形が一意に定まらない（運ぶ→運びました / 読む→読みました）
   ため機械変換できません。件数僅少につき手作業で足ります。

### 全件検証の結果

目視サンプリングでは9万件規模を検証しきれないため、`tools/verify_changes.py` で
**全変更段落に対して成り立つべき不変条件**を機械的に確認しています。

変更段落 76,328 件（大小文字のみ 71,443 / 書き換え 4,885）。

大小文字変更の不変条件（全て違反 0）:

- 小文字化すると旧新が完全一致 → **大小文字以外は一切変わっていない**
- 文字数が不変 → 文字の挿入・削除が起きていない
- 日本語部分（かな・漢字・約物）が不変
- 訳文に新たに現れたトークンは全て**原文に同じ表記で存在する**

書き換え（体言止め変換）の不変条件（全て違反 0）:

- 見出し番号（`6.1.1. ` など）が保持されている
- 助詞で終わる断片になっていない
- 変換結果が空になっていない
- 末尾は漢字 4,880 / カタカナ 3 / ひらがな 2（外れ値5件は個別に目視確認済み）
- 最大の文字数減は 6 文字（「されています」→「」の語尾のみで、内容の欠落なし）

`tools/verify_changes.py` は今後の一括修正でも再利用できます。

### 既知の許容事項（欠陥ではない）

- 書き換え結果の 1,130 件（23%）で「AのBのC」と「の」が連続します。
  「応答の範囲の制限」のように文法上は正しく、技術文書の見出しとして通常の
  表現です。冗長さは残りますが変換前より劣化はしていません。
- 1文字の識別子は復元できません（`V.Credit_S` が `v.Credit_S` のまま等）。
  壊してはいないが直しきれていない状態で、W009と同じく判断が必要な領域です。

## 所見

**RFC7000帯だけE001が修正前から28件と突出して少なく、修正後も272件です**
（他帯は修正前 3,005〜21,314件）。この帯だけ別の手順・別エンジンで処理された
可能性が高く、原因を特定できれば新規翻訳の品質向上に転用できるかもしれません。

## 注意

このlinterは**原文と照合して決定的に判定できる違反のみ**を検出します。
訳語選択の妥当性、文の自然さ、文脈整合性は検出できません。
これらは `.agents/skills/review-translation` によるAIレビューの担当範囲です。
